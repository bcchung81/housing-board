# 지도 번들 데이터 정의서 (어댑터 매핑 포함)

- 번들 스키마 버전: **1.1.0** (1.0.0에 선택 필드만 추가. 1.0.0 번들도 그대로 읽힙니다)
- 상태: **확정** — 지도 앱이 이 문서대로 번들을 읽습니다(인천 계양구·광주 광산구·전남 나주시 번들로 확인).
- 읽는 분: 지도 번들을 만드는 사람(수집·컴파일러 작성자)과, 지도에 올라간 값을 검토하는 사람
- 한 줄 요약: 번들 JSON을 이 문서대로 만들면, 화면은 **별도 설정 없이** 그 지역을 보여 줍니다. 값이 어디에 어떤 모양으로 나오는지, 비어 있으면 화면이 어떻게 동작하는지가 모두 여기 있습니다.

입력 쪽 규격(CSV)은 `정의서.md`에 있습니다. 이 문서는 그 **다음 단계**인 번들(JSON)과 화면을 다룹니다.

```
입력 CSV·GeoJSON ──(파이프라인: 상태 계산·윤곽 생성)──▶ 번들 JSON ──(어댑터 region.js)──▶ 지도 화면
   정의서.md 규격                            이 문서의 3절                  이 문서의 4~5절
```

## 1. 파일 구성과 불러오는 순서

지역마다 폴더 하나(`regions/<slug>/`)가 있고, 지역 목록 파일 하나(`regions/index.json`)가 모든 지역을 가리킵니다.

| 파일 | 필수 | 내용 | 화면에서의 용도 |
|---|---|---|---|
| `regions/index.json` | 예 | 지역 목록, 기본 지역, 공개 여부 | 처음 열 지역 결정, 지역 선택기 |
| `regions/<slug>/region.json` | 예 | 지역 설정: 제목, 시작 위치, 지구, 출처, 상태 순서 | 제목·문구, 지도 시작 위치, 지구 경계, 범례 |
| `regions/<slug>/projects.json` | 예 | 단지 목록(단지가 0개여도 파일은 있어야 함) | 단지 카드·목록·지도의 블록과 동 |
| `regions/<slug>/buildings.json` | 예 | 지역의 건물 윤곽과 높이(GeoJSON) | 지도의 3차원 건물 |
| `regions/<slug>/context.json` | 아니오 | 지하철역·학교 위치 | 카드의 "가까운 역·학교", 역 반경 |

**불러오는 순서:** 로딩 화면 → `index.json` → 지역 결정(주소의 `?region=` → 없으면 `default: true`인 지역) → `region.json` → `projects.json`·`buildings.json`·`context.json`을 동시에 → 어댑터 변환 → 화면.

**실패할 때 화면 동작**

| 상황 | 화면 |
|---|---|
| `?region=`이 목록에 없음 | 지역 목록과 함께 안내 화면 |
| `region.json`·`projects.json`·`buildings.json` 불러오기 실패 | 오류 안내(어느 파일인지 표시) |
| `context.json`이 없음(404) | 오류 아님. 역·학교 기능만 숨김 |
| `projects.json`의 단지가 0개 | 건물만 보이는 **빈 지역 화면**(5.4절) |

## 2. 공통 규약

| 항목 | 규칙 |
|---|---|
| 좌표 | WGS84 `[경도, 위도]`. 소수 6자리 이내 |
| 날짜 | `YYYY-MM-DD`. 입주 월은 `YYYY-MM` |
| 인코딩 | UTF-8 JSON(BOM 없음) |
| 모르는 값 | **키를 빼거나 `null`**. 빈 문자열 `""`·`0`으로 채우지 않습니다 |
| 버전 | 모든 번들 파일의 `schema_version`은 `주.부.패치`. 화면은 현재 주버전과 직전 주버전을 읽습니다 |
| 정본 | 필드의 형식·필수 여부의 정본은 `schemas/bundle/*.schema.json` |

### 3.4 `regions/<slug>/buildings.json` (GeoJSON)

| 필드 | 필수 | 뜻 | 화면 용도 |
|---|---|---|---|
| `type` | ● | `FeatureCollection` | |
| `meta.basis` | ● | 자료 기준일 `YYYYMMDD` | 푸터의 "○○ 기준" |
| `meta.factor` | | 층고 환산표(아래) | 층수로 높이를 추정할 때 |
| `features[].geometry` | ● | `Polygon`/`MultiPolygon` | 건물 윤곽 |
| `features[].properties.eh` | ● | 화면에 그릴 높이(m, 0 이상) | 3차원 높이 |
| `properties.src` | | `공식높이`/`층수환산`/`정보없음` | 건물 카드의 높이 안내, 색조 |
| `properties.h` | | 공식 높이(m) | `src`가 `공식높이`일 때 |
| `properties.f`, `b` | | 지상·지하 층수 | |
| `properties.u`, `n`, `a`, `d` | | 용도, 건물명, 사용승인 연도, 법정동 | 건물 카드 |
| `properties.x` | | `1`이면 높이·층수 불일치 의심 | 건물 카드 |

**`eh`를 정하는 순서(번들 작성자 규칙):** 공식 높이 `h`가 0보다 크면 `eh = h`(`src` = `공식높이`) → 아니면 지상층수 `f`가 있으면 `eh = f × 층고`(`src` = `층수환산`) → 둘 다 없으면 `eh = 3`(`src` = `정보없음`, 3 m 평면으로 그려지고 실제 높이가 아니라고 안내).

**`meta.factor`의 키:** `공동주택_1-5`, `공동주택_6-10`, `공동주택_11-15`, `공동주택_16-20`, `공동주택_21+`(층수 구간별 m/층)과 용도별 값. 키가 없으면 화면은 **2.85 m/층**을 씁니다.

## 4. 어댑터 변환 규칙

어댑터(`assets/js/region.js`)가 번들을 화면 코드가 쓰는 내부 모양으로 바꿉니다. 번들 작성자가 알아야 할 규칙은 아래가 전부입니다.

### 4.1 필드 매핑

| 번들 | 화면 내부 | 비고 |
|---|---|---|
| `id` | `id` | 내부 식별용. 주소의 `?block=`도 인식 |
| `label` | 화면에 보이는 단지 이름 | 카드·목록·지도 표지·HUD 모두 `label` |
| `outline.poly` | `poly` | |
| `outline.tier`, `outline.how` | 윤곽 문구 | 5.3절 |
| `dongs[].floorsAbove` | `dongs[].floors` | 층수도 높이도 없으면 그 동은 3D로 그리지 않음(4.3절) |
| `dongs[].heightM` | 동 높이 | 있으면 층수 환산보다 우선 |
| `contractAmountM` | `contractM` | |
| `progress.start/end/source` | 같은 이름 | |
| `sources[]` | 출처 문구 | `region.sources[].label`을 이어 붙임 |
| `sponsorClass` | 민간 스타일 여부 | `private_on_public_land`면 회색 톤 |
| `events[]`, `flags[]`, `zoneId`, `sponsor.type` | (사용 안 함) | 번들에는 보존 |

### 4.2 입주 표기 (`moveIn`)

| 번들 값 | 화면에 보이는 값 |
|---|---|
| `"2029-06"` | `입주 2029.06` (내부 형식 `2029.06`) |
| `"2028-09-30"`(날짜) | `준공 예정 2028-09-30` |
| `null`이고 `progress.end` 있음 | `준공 예정 <progress.end>` |
| `null`이고 `progress.end`도 없음 | `입주 시기 미정` |
| `null`이고 `status`가 `입주 단계` | `입주 일자 미상` (이미 입주한 단지에 '미정'은 어색해서 `progress.end`가 있어도 이 문구) |

### 4.3 층수와 높이

- 동 높이: `heightM`이 있으면 그 값. 없고 `floorsAbove`가 있으면 `floorsAbove × 층고`(층고는 `buildings.meta.factor`, 없으면 2.85 m). 둘 다 없으면 그 동은 3D로 그리지 않고 층수 분포에서도 뺍니다. `heightM`만 있고 `floorsAbove`가 없으면 층수는 `round(heightM ÷ 2.85)`로 표시합니다. (3 m 평면은 지도에 이미 있던 **기존 건물**의 높이를 모를 때 쓰는 표시입니다.)
- 동 카드의 높이 안내: `heightM`이 있으면 "높이 N m", 층수로 구했으면 "높이 약 N m (추정)".
- `dongs`가 없는 단지: 윤곽만 그려지고 카드의 층수는 "미확인".

### 4.4 단지 목록 순서

1. `region.projectOrder`가 있으면 그 순서 그대로(목록에 없는 단지는 뒤에 4번 규칙으로).
2. 없으면 상태 순서 `분양중 → 건설 단계 → 준공 임박 → 입주 단계 → 계획`.
3. 같은 상태 안에서는 세대수가 많은 순(`units`가 `null`이면 0으로 봄).
4. 그래도 같으면 `label` 문자열 순.

### 4.5 상태 → 종류·단계

| 상태 | 내부 종류 | 사다리 단계(`계획·분양·건설·입주` 4칸) |
|---|---|---|
| 계획 | `plan` | 0 — 모든 칸이 비어 있음 |
| 분양중 | `sale` | 1 |
| 건설 단계 | `build` | 2 |
| 준공 임박 | `soon` | 3 (지금처럼 "입주" 칸이 현재 단계) |
| 입주 단계 | `move` | 4 — **네 칸 모두 완료로 표시**(현재 단계 칸 없음) |

### 4.6 값이 비어 있을 때

| 비어 있는 값 | 화면 동작 |
|---|---|
| `units` | 카드 큰 글씨·목록·HUD에 "세대수 미확인", 합계에서는 빠지고 "세대수 미확인 ○곳 제외"가 붙음 |
| `dongCount` | "○개동" 표시를 생략 |
| `progress` | 공정율 줄·막대 없음. "공정율" 보기에서는 진행 없는 것으로 그림 |
| `progress.start/end` | 공사기간 줄 생략. "입주 시기" 보기는 `moveIn`만으로 근사 |
| `dongs` | 윤곽만. 층수 "미확인" |
| `builder`, `contractAmountM`, `note` | 그 줄이 나오지 않음 |
| `sources` | "출처:" 줄 생략 |
| `outline.how` | 윤곽 문구에 괄호 설명 없음 |
| `context.json` 전체 | 역·학교 기능 숨김 |
| 단지 0개 | 빈 지역 화면 |

## 5. 화면 표기 규칙

### 5.1 상태 5종

| 상태 | 지도 무늬 | 낮 색 | 밤 색 | 칩·글자(낮, 흰 바탕 대비 4.5:1 이상) |
|---|---|---|---|---|
| 분양중 | 단색 | `#D55E00` | `#FF8A3D` | `#A84800` |
| 건설 단계 | 사선 해칭 | `#0072B2` | `#47B0F7` | `#005C91` |
| 준공 임박 | 점무늬 | `#009E73` | `#2FD6A2` | `#00755A` |
| 입주 단계 | **격자 무늬(신규)** | `#CC79A7` | `#E88DC0` | `#A23B7C` |
| 계획 | 점선 윤곽 | `#5C6068` | `#A8B0C0` | `#4A4E56` |

색각 이상에서도 구분되도록 색과 무늬를 함께 씁니다. 새 색은 Okabe-Ito 팔레트의 다른 색입니다. 칩·글자 색은 흰 바탕에서 4.5:1 이상(입주 단계 `#A23B7C`는 6.1:1)임을 계산해 확정했습니다.

### 5.2 공공택지 위 민간 단지 (`sponsorClass = private_on_public_land`)

- 상태와 무관하게 **회색 단색 면**으로 그립니다(낮 `#8A8680`, 밤 `#A39F97`). 상태 무늬는 쓰지 않고, 상태는 카드·배지·HUD의 글자로 구분합니다.
- 카드 칩 줄에 상태 칩과 함께 "공공택지 민간" 칩이 붙습니다.
- 옵션 패널에 "공공택지 민간 단지" 스위치가 생깁니다(기본 켜짐, 주소 `priv=0`으로 끔). 이 지역에 민간 단지가 하나도 없으면 스위치가 보이지 않습니다.
- 범례에 "공공택지 민간" 줄이 생깁니다(민간 단지가 있고 스위치가 켜져 있을 때만). 합계 막대에도 별도 묶음으로 나옵니다.
- 목록·HUD·합계에서 세대수를 모르는 단지는 "세대수 미확인"으로 나오고 합계에서는 빠집니다.

### 5.3 자동으로 만들어지는 문구

번들에 문장을 통째로 넣지 않습니다. 아래 템플릿으로 화면이 만듭니다.

| 위치 | 만드는 방법 |
|---|---|
| 카드 "출처:" | `project.sources`의 각 id를 `region.sources[].label`로 바꿔 ` · `로 이음. 비면 줄 생략 |
| 카드 윤곽 줄 | 등급 문구 + (`outline.how`가 있으면 ` (how)`). "윤곽:" 접두어는 붙이지 않음 |
| 푸터 윤곽 문장 | 지역 안에서 쓰인 등급들의 문구를 `, `로 이어 마지막에 `입니다.` |
| 푸터 공정율 문장 | `progress.source`가 있는 출처 label들 → `공정율은 ○○ 기준입니다.` |
| 푸터 역·학교 문장 | `context.json`이 있으면 `역·학교는 ○○입니다.`(`context.source`의 이름) |
| 브라우저 탭 제목 | `주택파동 공급 지도 (<region.name>)` |
| 좌상단 소제목 | `region.title` |
| 메타 설명 | `region.description` |

**윤곽 등급 문구**

| 등급 | 문구 |
|---|---|
| `official` | 블록 윤곽은 공식 자료 |
| `building` | 동 윤곽은 실제 건물 자료 |
| `schematic` | 동 윤곽은 근사값(10~20 m) |

### 5.4 지역 선택기·미리보기·빈 지역

- **지역 선택기:** 공개 목록에 지역이 **2개 이상**일 때만 헤더에 드롭다운이 생깁니다. 고르면 `?region=<slug>`로 이동하며 다른 주소 매개변수는 유지하고 `block`만 지웁니다.
- **미리보기 배너:** `visibility`가 `preview`인 지역을 열면 상단에 "미리보기 — 공개 전 자료입니다"가 나옵니다. `preview` 지역은 운영 사이트에는 파일 자체가 올라가지 않습니다.
- **빈 지역:** 단지 목록 영역에 "이 지역에는 아직 표시할 단지가 없습니다. 자료가 들어오면 이곳에 나타납니다."가 나오고, 합계·다음 일정·타임라인 영역은 숨겨집니다. 단지는 있지만 입주·준공 날짜가 하나도 없으면 타임라인 영역만 숨겨집니다.

### 5.5 주소 매개변수

| 매개변수 | 값 | 동작 |
|---|---|---|
| `region` | slug | 열 지역. 없으면 기본 지역 |
| `block` | 단지 `label` 또는 `id` | 그 단지 카드를 열고 지도로 이동 |
| `mode` | `floors`/`progress`/`time` | 보기 기준 |
| `theme` | `night` | 야간 |
| `ctx`, `ring`, `hud`, `priv`, `aa` | `0`/`1` | 역·학교, 역 반경, HUD, 공공택지 민간 단지(`priv=0`이면 숨김), 안티앨리어싱 |

### 5.6 반투명 유리

지도 위 단지 표지(HUD)·HUD 요약·상세 카드는 뒤 지도가 비치는 반투명 유리 질감입니다(낮 흰색 84~86%, 밤 남색 76~80%, 흐림 6 px). `backdrop-filter`를 못 쓰는 브라우저는 거의 불투명(94% 이상)으로 바뀝니다. 가장 밝은 지도와 가장 어두운 지도 위에서 본문·보조·상태 글자의 대비가 4.5:1 이상인지 `tests/js/glass.test.cjs`가 확인합니다.

## 7. 버전과 호환

- 번들 스키마는 **입력 규격과 별도 버전**을 가집니다(입력 `1.0.0` 유지, 번들 `1.1.0`).
- **1.0.0 → 1.1.0은 선택 필드 추가뿐입니다:** `project.note`, `project.builder`, `project.contractAmountM`, `progress.start`, `progress.end`, `progress.source`, `region.projectOrder`. 1.0.0 번들은 이 필드가 없는 것으로 읽습니다.
- 필드 삭제·의미 변경·필수 필드 추가는 주버전을 올립니다. 화면은 현재 주버전과 직전 주버전을 읽습니다.

## 8. 번들 작성자 점검표

- [ ] 모든 파일에 `schema_version`이 있고, `index.json`의 `default: true`가 정확히 하나다
- [ ] `projects.json`이 단지 0개여도 존재한다. `buildings.json`에 `meta.basis`가 있다
- [ ] 단지마다 `id`는 지역 안에서 유일하고 한 번 정하면 바꾸지 않았다. `label`은 지도에 짧게 보일 이름이다
- [ ] `status`는 입력 이벤트에서 계산한 값이고 5개 중 하나다. `region.statusOrder`와 같은 5개 목록이다
- [ ] 공공택지 위 민간 단지는 `sponsorClass`가 `private_on_public_land`다
- [ ] 동의 `floorsAbove`는 **지상** 층수다(`floorsBelow`와 바뀌지 않았다). 높이/층이 2.4~4.5 m 안인지 확인했다
- [ ] 모르는 값은 키를 뺐거나 `null`이다. `0`이나 `""`로 채우지 않았다
- [ ] 단지가 쓴 출처 `id`가 모두 `region.sources`에 있다. `redistributable`이 `Y`가 아닌 출처의 데이터는 `visibility: preview`로 뒀다
- [ ] 번들을 `python3 tools/regiontools/check_bundle.py regions/<slug>`로 검증했다 (S2 구현 후 제공)

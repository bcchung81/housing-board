# 더주택 비지도 화면 디자인 통일 핸드오프

작성일: 2026년 10월 19일 · 대상: 디자이너, 프런트엔드 개발자, 화면 검수 담당자 · 상태: 구현 전 개선안

일반사용자 종합상황판(`/citizen`)의 **웜 뉴트럴 바탕, 딥 잉크 요약 카드, 클레이 강조색, 짧고 구조적인 정보 표현**을 지도 외 화면의 공통 디자인으로 확장한다. 카드의 면·반경·여백뿐 아니라 제목, 대표 수치, 설명, 출처의 위치까지 통일한다. 정책담당자 화면은 이 디자인 안에서 표의 정보 밀도와 판정 정보를 유지한다.

현재 구현의 정본은 `app/globals.css`다. 이 문서의 ‘목표 규격’은 다음 구현을 위한 제안이며, 기존 `DESIGN.md`와 코드에 이미 적용된 결정으로 간주하지 않는다. 이번 산출물은 문서와 점검 근거이며 화면 코드는 변경하지 않았다.

## 1 적용 범위와 점검 근거

### 화면 범위

‘전체 화면’은 현재 운영 경로와 그 안의 상세·인쇄 상태를 포함한다. 예전 주소가 이동시키는 화면은 중복으로 새로 디자인하지 않는다.

| 화면 | 경로 및 상태 | 이번 작업의 역할 |
|---|---|---|
| 일반사용자 종합상황판 | `/citizen` | 기준 화면. 요약·신청·청약 단지와 공통 조작 규칙을 추출 |
| 사업 찾기 | `/citizen/projects`, `?id=` 상세 | 최우선 적용 |
| 공급 일정 | `/citizen/schedule` | 최우선 적용 |
| 정책담당자 종합상황판 | `/` | 지시 카드·판정·단계·실적·기관 패널에 공통 규격 적용 |
| 사업 | `/projects`, `?id=`, 후보 간단 보기 | 필터·요약·목록·서랍 적용. 후보 상태는 소스 점검 |
| 월간 보고 | `/projects?print=1` | 화면 미리보기와 인쇄용 예외 정의 |
| 지역 공급 | `/region`, 시도·시군구·종류 선택 | 예정·실적·동네 여건 카드 적용 |
| 데이터 원본 | `/sources`, 펼침·세부 근거 | 수집·연결·연도·표·설명 적용 |
| 월 상세 | `/month/[id]` | 실적이 있는 달과 예정만 있는 달 모두 적용 |
| 기관 상세 | `/agency/[id]` | LH·지자체 실적형, GH 사업형, SH·국방부 원천형 모두 적용 |

**지도 제외 경계:** `/map`의 헤더·사이드 패널·팝업·컨트롤을 포함해 지도 화면 전체를 유지한다. `/citizen`의 내장 지도·시간 띠·지도 범례·지역 순위, `/region`의 내장 지도도 이번 변경 대상에서 제외한다. 그 바깥 카드의 간격·제목 규격이 지도 슬롯의 크기나 겹침을 바꾸는지는 회귀 검수한다. 지도 연결 링크의 모양은 비지도 화면 안에서만 통일한다.

### 점검 방법

- 현재 작업 디렉터리의 미커밋 변경을 포함한 최신 파일을 기준으로 했다. 브랜드명·헤더·종합상황판을 수정 중인 기존 작업은 보존했다.
- 실제 로컬 앱 `http://127.0.0.1:8000`에서 위 경로와 대표 상태를 열고 DOM, 계산된 색·반경·타이포그래피, 카드 치수, 제목·본문 구조를 수집했다. 브라우저 관측 크기는 1512×838, 기본 다크 테마다.
- 스타일·부품·라우팅·문구 함수와 `PRODUCT.md`, `DESIGN.md`를 대조했다. 라이트 값은 CSS에서 추출했으며 이번 브라우저 수집은 다크 화면 중심이다.
- 요청한 Sequential Thinking MCP는 `@modelcontextprotocol/server-sequential-thinking`을 임시 stdio 서버로 실행하고 `sequentialthinking`을 6회 호출했다. MCP 설정을 영구 변경하지 않았다. 결과 영수증은 아래 근거 파일에 저장했다.
- 스크린샷 캡처가 시간 초과로 실패했다. 따라서 이 문서는 픽셀 단위 시각 검수, 모바일 실기기 검수, 전 상태 기능 검수의 완료 보고서가 아니다. 구현 인수 시 10절의 화면 캡처 검수를 수행한다.

이미 공통화된 Noto Sans KR, 400/700 굵기, 14px/16px 본문, 14px 바깥 반경, 1px 테두리, `.ui-card` 계열과 `InfoTip`은 유지한다. 새 카드 세트를 처음부터 만들기보다 이 기반의 역할과 범위를 정리한다.

`DESIGN.md`에는 같은 날 초기 규격과 최신 결정이 함께 남아 있다. 예를 들어 정책 지시 카드는 본문에 74px·두 줄이 남아 있지만 마지막 결정에는 최소 112px·세 단 구조가 기록되어 있다. 작업 시작 시 최신 구현과 마지막 결정을 기준으로 정리하고, 과거 값을 다시 적용하지 않는다.

## 3 목표 디자인 원칙

1. **웜 바탕 위에 카드 경계를 읽힌다.** 기본 카드 전체를 채색하지 않는다. 딥 잉크는 대표 요약, 살구색은 신청 행동에 제한한다.
2. **제목은 이름, 수치는 별도 영역에 둔다.** ‘어떤 정보인지’와 ‘얼마인지’를 다른 시각 역할로 구분한다.
3. **같은 의미는 같은 표현을 쓴다.** 선택은 클레이, 단계는 기존 6단계색, 정상·주의·지연은 기존 판정색이다. 클레이를 지연색으로 사용하지 않는다.
4. **필요한 사실을 숨기지 않는다.** 범위 차이, 실제·예정, 잠정치, 날짜 불일치, 자료 부족은 읽는 위치에 남긴다. 계산식·정의·긴 출처는 설명 팝오버에 둔다.
5. **색과 밀도를 분리한다.** 일반사용자는 본문 16px와 쉬운 표현, 정책담당자는 표 14px와 정확한 판정 정보를 사용한다. 브랜드 통일을 위해 두 관점의 데이터나 업무 용어를 합치지 않는다.

| 소제목 | 16/700/1.3 | 표 안 연도 그룹 제목은 기존 18/700 예외 유지 가능 |
| 일반사용자 본문·표 | 16/400/1.6 | 문장·사업명·일정 |
| 정책담당자 본문·표 | 14/400/1.5 | 표와 조밀한 업무 정보 |
| 메타·보조·범례 | 14/400/1.5 | 핵심 사실을 저대비로 흐리지 않음 |
| 각주·축 | 정책 화면만 12/700/1.5 | 일반사용자 화면은 최소 14 |

`12·14·16·18·20·24·30·38px` 기존 크기 체계는 유지한다. 38px는 이번 확장에 새로 사용하지 않는다. 단위는 숫자 옆 14px로 구분하되 숫자와 줄바꿈되지 않게 묶는다.

## 5 카드 유형과 구성 계약

### 카드 유형

| 유형 | 쓰임 | 면과 구조 | 높이·정보 규칙 |
|---|---|---|---|
| 기본 구역 `section` | 표·차트·일정·원천 | 웜 카드 면, 14px, 여백 20px | 제목 아래 콘텐츠. 기본 선택 |
| 대표 요약 `tone=summary` 제안 | 기존 공급 예정 총량, 정책 핵심 요약 | 딥 잉크 단색, 내부 글자 토큰 덮기 | 숫자 30, 보조 14, 내부는 선으로 구분 |
| 신청 `tone=apply` 제안 | 현재 접수·신청 행동 | 살구 면, 신청 경계 | 공고명 → 상태·기간 → 대상·가격. 공고별 중첩 카드 대신 행 |
| 수치 타일 `tile` | 독립된 한 지표 | 기본 카드 면, 8px, 여백 12/16 | 라벨 14 → 값 20 또는 대표값 24 → 보조 14 |
| 안쪽 묶음 `inset` | 단계·기본 사실 묶음 | 안쪽 면, 8px, 1px, 그림자 없음 | 여백 8/10. 비교 숫자나 단계끼리만 그룹화 |
| 데이터 행 `row` | 공고·일정·근거·순위 외 목록 | 바탕 투명, 아래 1px 선 | 일반사용자 56px, 정책 44px 이상 |
| 사실 안내 `FactNote` 제안 | 일정 경과·원천 차이·자료 부족 | 안쪽 면 또는 투명 행, 글자 우선 | 본문 한 문장과 필요 시 설명 팝오버 |

`tone`은 색의 역할이고 `variant`는 구조다. `Card`에 구조와 색을 뒤섞은 새 변형을 계속 늘리지 않는다. 제안한 `tone`을 구현하면 정적 페이지용 `.ui-card-summary`, `.ui-card-apply`와 같은 규칙을 쓰게 한다.

대표 요약은 같은 화면 구역에서 하나만 강조하는 것을 기본으로 한다. 정책 지시 카드 6개는 현 구조·순서를 유지하고 웜 기본 타일로 통일한다. 모두를 잉크 면으로 바꾸거나 새 총량 카드를 추가하지 않는다. 기존 정책 요약 중 잉크 면으로 승격할 대상은 시안에서 한 곳을 정한다.

### 카드의 정보 슬롯

```text
┌ 카드 제목  (설명)  [범위·원천]                    상세 링크 ┐
│ 대표값 24px + 단위          보조 건수·기간 14px             │
│ 표 / 차트 / 일정 / 사실 목록                               │
│ 필요한 경우: 자료 한계 한 문장 또는 보조 사실               │
└──────────────────────────────────────────────────────────┘
```

- **제목:** ‘앞으로 12개월’, ‘사업 목록’, ‘수집 상태’처럼 주제만. 최소 높이 44px이며 2줄까지 허용한다.
- **범위:** ‘남양주시 · 공공 사업’, ‘경기 · 모든 주택’처럼 지표의 범위를 명시한다. 제목이 좁아지면 범위 묶음이 다음 줄로 내려간다.
- **대표값:** 기존 데이터에서 추출한다. 수치를 강조하기 위해 새 합계·순위·정책 판단을 만들지 않는다. 대표값이 없는 표 카드에는 이 행을 두지 않는다.
- **보조값:** 기간·건수·기준일을 14px로 배치한다. 한 정보를 제목·대표값·하단에 반복하지 않는다.
- **행동:** 오른쪽 조용한 `PanelLink`를 기본으로 한다. 주 행동만 채움 단추를 사용한다.

기존 `PanelHead`는 제목, 설명, 범위, 행동을 담당하게 유지한다. 대표값 행은 별도 `MetricRow`로 분리해 제목의 `<span>`을 계속 늘리지 않는다. 아래 이름은 신규 구현 계약이며 현재 존재하는 부품으로 오해하지 않는다.

| 부품 | 입력 계약 | 비고 |
|---|---|---|
| `MetricRow` 제안 | 대표 라벨·값·단위, 보조 항목 배열 | 값·단위 폭 유지, 빈 슬롯 생략 |
| `FactNote` 제안 | 사실 본문, 설명, 선택적 링크 | 중립·주의·오류 역할 분리. 일반 지연 사실은 중립 |
| `DataMeta` 제안 | 범위, 자료 기준일, 수집일, 원천, 한계 | 기준일과 수집일을 다른 필드로 유지 |
| `FilterBar` 제안 | 검색, 지역, 단계·지표, 추가 조건 | 데스크톱 정렬과 좁은 폭의 줄 순서 공통화 |
| 기존 `InfoTip` | 짧은 접근성 이름, 정의·근거 내용 | 제목 옆 고정, hover 전용 금지 |

정적 `/citizen`을 React로 다시 만드는 작업은 포함하지 않는다. 공유 CSS 부품을 내보내 정적 템플릿과 Next 부품이 같은 규칙을 사용한다.

## 6 서술형 텍스트와 데이터 표기 규격

### 정보별 노출 위치

| 정보 | 보이는 표현 | 위치·길이 |
|---|---|---|
| 카드 주제 | 짧은 명사구 | 제목, 데스크톱 1줄 권장·최대 2줄 |
| 범위·원천 유형 | ‘공공 사업’, ‘모든 주택(민간 포함)’ | 제목 옆 또는 바로 아래. 생략 금지 |
| 핵심 사실 | ‘준공 예정일이 19개월 지났어요’ | 일반사용자 본문 16, 중립색. 줄 수 제한 없이 내용 보존 |
| 상태 판정 | ‘주의’, ‘지연’, ‘장기 지연’과 해당 값 | 정책 화면의 상태 열·요약. 색과 글자 함께 |
| 정의·계산·상세 출처 | 짧은 소제목 + 설명 | `InfoTip` 안 본문. 긴 문단은 정의 목록으로 분할 |
| 자료 기준 | ‘자료 기준 2026.10.13’ | 페이지 또는 데이터 구역 메타 14 |
| 실제·예정·잠정 | 날짜 옆 ‘예정’, ‘완료’, ‘잠정’ | 값에 붙여 표시. 팝오버에만 숨기지 않음 |
| 데이터 한계 | ‘시도 전체 값’, ‘원천 날짜 다름’, ‘기관 판정 자료 없음’ | 관련 범위·날짜·상태 옆 |
| 빈 상태 | ‘이 조건의 사업이 없어요’ | 본문 한 문장 + 조건을 푸는 링크 |
| 오류 | ‘일정을 불러오지 못했어요’ | 본문 한 문장 + 실제 가능한 재시도 |

일반사용자는 ‘~예요/~어요’, 정책 화면은 짧은 명사구 또는 ‘~합니다’를 사용한다. 같은 문장의 끝맺음을 화면 안에서 섞지 않는다. 기획·구현 설명을 사용자의 본문에 노출하지 않는다.

본문 한 문단은 1~2문장을 권장하고, 긴 읽기 영역은 최대 65ch로 제한한다. 표·정의 목록의 폭은 이 제한을 적용하지 않는다. 본문은 1.6 또는 1.5 줄 높이, 문단 간격 8px, 설명 묶음 간격 12px다. 사실 문장을 말줄임하거나 12px로 낮추지 않는다.

### 현재 표현과 변경 예시

아래 숫자는 점검 시점의 예시다. 운영 화면에는 기존 함수가 계산한 값을 바인딩한다.

| 현재 패턴 | 목표 표현과 배치 |
|---|---|
| 제목 ‘수도권 · 사업 262곳 · 22만 7,976호’ | 제목 ‘사업 목록’ / 범위 ‘수도권 · 공공 사업’ / 대표값 ‘22만 7,976호’ / 보조 ‘262곳’ |
| 제목 ‘앞으로 12개월 · 준공 예정 1곳 · 629호’ | 제목 ‘앞으로 12개월’ / 지표 ‘준공 예정’ / 대표값 ‘629호’ / 보조 ‘1곳’ / 범위 ‘남양주시 · 공공 사업’ |
| 제목 ‘단계 타임라인 장기 지연 · 당초 일정 없음’ | 제목 ‘단계 타임라인’ / 상태 ‘장기 지연’ / 한계 메타 ‘당초 일정 없음’. 각각 의미와 설명 연결 |
| ‘2026년은 8월까지(잠정)’ | ‘2026년 1~8월 · 잠정’. 차트의 해당 연도와 연결하고 전체 연도 실적으로 보이지 않게 표시 |
| `D-343` | 일반사용자 화면은 ‘343일 뒤’ 제안. 날짜는 그대로 유지하고 현재 날짜 기준으로 다시 계산 |
| 자료 미정인데 숫자 0과 비슷하게 보임 | ‘일정 미정’, ‘호수 미정’, ‘자료 없음’으로 구체화. 확인된 0만 `0호` |

일반사용자 사업 찾기의 긴 지연 문장은 사실 전달에 필요하므로 유지한다. 목록 폭이 좁으면 다음 줄로 내리고 상세에서도 같은 문구 함수를 사용한다. 정책 상태 배지로 대체하거나 ‘정상’이라는 판단을 추가하지 않는다.

### 숫자와 날짜

- 원장 호수는 `호`, 사업 건수는 일반사용자 `곳`·정책 `건`을 유지한다. 청약홈 원천의 `세대`는 `호`로 강제 변환하지 않는다.
- 대표 합계는 기존 `hoBig` 같은 공통 함수의 ‘22만 7,976호’, 표의 수량은 ‘1,224호’를 따른다. 표 머리에 단위가 명시되어 있으면 칸의 숫자만 표시하는 기존 형식도 허용한다.
- 비율·공정률의 반올림은 기존 공통 함수를 유지한다. 모양 통일을 위해 계산 정밀도를 바꾸지 않는다.
- 짧은 날짜는 `2026.10.13`, 월은 `2026.10`, 일반사용자 상세의 긴 날짜는 `2026년 10월 13일`로 역할을 구분한다.
- 원천이 연도·월까지만 제공한 날짜를 임의의 일자로 완성하지 않는다. ‘미정’과 ‘예정’, ‘실제’는 다른 필드다.
- 사업명은 데이터명을 변경하지 않는다. 짧은 이름을 쓰는 화면은 원래 이름을 전체 이름 보기·상세·읽기 도구로 제공한다. 중요한 본문 정보를 `title` 속성에만 의존하지 않는다.

## 7 필터와 상호작용 규격

| 역할 | 목표 형태 | 적용 위치 |
|---|---|---|
| 지역 한 곳 선택 | `.ui-tabs-seg` 잉크 채움 | 일반사용자 지역 탭, 정책 지역 탭 |
| 단계·지표 한 개 선택 | `.ui-tabs-line` 밑줄 | 사업 찾기 단계, 착공·준공 지표 |
| 복수 종류 선택 | 외곽선 단추·체크 가능한 필터 | 모집·준공·입주 복수 선택. 한 개 선택 탭과 혼동 방지 |
| 정책·기관 등 긴 조건 | 현 `ChipMenu` | 이름·선택값·초기화 위치 공통화 |
| 선택된 조건 요약 | 제거 가능한 칩 | 시군구·추가 조건. 전체 필터를 칩으로 바꾸지 않음 |
| 검색 | `.ui-search`, 높이 40 | 화면 목적에 맞는 placeholder, 초성 안내는 도움말 |
| 더 보기·원문 | 텍스트 링크 + lucide 방향 아이콘 | 원문은 새 창임을 읽기 도구에 전달 |

거르기 단추는 `role=group`와 `aria-pressed`, 실제 탭 패널 전환만 tab 의미를 사용한다. 라우팅 링크는 링크 의미를 유지한다. 선택·가리킴·초점은 서로 구분한다.

선택은 1px 경계나 잉크 채움·밑줄로 표현하고, 키보드 초점만 2px 링을 사용한다. 판정·단계색은 해당 의미가 있을 때만 쓴다. 일반 카드에는 장식 아이콘, 색 띠, 추가 배지를 붙이지 않는다.

좁아지면 검색 → 지역 → 단계·지표 → 추가 조건 순으로 줄을 나눈다. 900px 이하에서는 필터를 본문 폭 안에 쌓고, 520px 이하에서는 탭을 줄바꿈한다. 본문 전체의 가로 스크롤로 조작을 숨기지 않는다. 표가 읽기 어려운 폭에서는 일반사용자 사업 행을 세로 정보 목록으로 바꾸는 현 동작을 유지한다.

정적 데이터 카드는 hover로 떠오르지 않게 정리한다. 클릭 가능한 타일만 현재 `card-lift`를 사용하며, 표 행·일정 행은 면·밑줄로 반응한다. 현 지시 카드의 연동·선택 동작과 reduced-motion 대응은 유지한다.

## 8 화면별 변경 명세

### 일반사용자 종합상황판

기준: `tools/design/public-mock/template.html`, `app/globals.css`, 빌드 진입 `tools/design/public-mock/build.js`.

- 딥 잉크 공급 요약과 살구색 지금 신청 카드를 기준 표본으로 유지한다. 요약 내 라벨 14, 숫자 30, 단계 행 16, 메타 14의 역할을 다른 화면에 전달한다.
- 청약 단지는 기본 구역 카드, 머리와 행의 같은 열 트랙, 최소 56px 행을 유지한다. 칼럼은 현재 이름·세대·특별공급·주택형·일정·입주·시공·시행 순서를 따른다.
- ‘지금 신청’ 빈 상태도 일반 문장 규격으로 통일하고, 이웃 공고가 있으면 행 목록으로 연결한다. 가짜 신청 버튼을 추가하지 않는다.
- 일반사용자에게 보이는 `D-`는 쉬운 남은 일수 표현으로 교체한다. 원천·합계·검색·청약 범위는 변경하지 않는다.
- 내장 지도 영역은 기준 디자인을 추출하는 데도 지도 변경을 전제하지 않는다.

완료 기준: 대표·신청·목록 세 카드 역할이 분명하고, 단계 필터가 청약 단지를 필터링하는 것으로 오해되지 않도록 기존 설명 연결이 유지된다.

## 9 구현 순서와 변경 지점

### 지도에 번지지 않는 적용 방법

현재 `app/globals.css`는 앱·정적 citizen·지도가 공유한다. `:root`와 `.dark`를 바로 웜 배색으로 바꾸거나 `data-page=citizen`을 모든 화면에 붙이면 지도 토큰이나 청약 표 전용 치수까지 영향을 받을 수 있다.

1. `html[data-design="warm"]` 같은 **비지도 브랜드 범위**를 신설한다. 이름은 제안이며, 실제 구현에서 하나로 확정한다.
2. 웜 중립·글자·주색·면·반경 등 공통 토큰만 이 범위로 추출한다. `--cz-map-*`, `--map-*`, `--ramp-*`, `--rank-*`, `--pj-cols` 같은 지도·특정 표의 값은 현 범위에 남긴다.
3. Next 대시보드 루트와 정적 citizen에 공통 범위를 적용한다. `app/(map)/layout.tsx`에는 적용하지 않는다. 루트 레이아웃이 나뉘므로 서로 이동할 때 문서 단위 분리가 유지되는지도 확인한다.
4. 정적 페이지용 globals 내보내기 층에 공통 범위를 포함한다. 빌드 후 결과 페이지가 원본 템플릿과 같은 값을 받는지 확인한다.
5. 요약·신청은 해당 카드 내부에서만 대비용 토큰을 덮는다. 정책 화면 전체의 단계색이나 본문색을 대표 요약 카드의 흰 글자로 덮지 않는다.
6. `Card`·`PanelHead` 등 공유 부품의 구조 변경이 `/map`의 공유 헤더·부품에 영향을 준다면 새 스타일을 비지도 범위에 한정한다.

| 3 | 카드·텍스트 공통화 | `components/ui/card.tsx`, `components/page.tsx`, `MetricRow`·`FactNote` 등 | 기본·요약·신청·수치·행·안내 표본 |

### 기존 시험과 연결

현 시험 중 `citizen-palette`, `tailwind`, `globals-tokens`, `no-hardcode`, `font-scale`, `shell`, `board-dir-fit`, `r3/r4-board`, `public-projects`, `screens-*`, `audience-toggle`, `maptheme`, `map-overview*` 관련 파일을 변경 영향에 따라 확인한다. 파일명만 보고 값을 일괄 바꾸지 말고 잠근 제품 약속과 실제 기대값을 읽는다.

기존 ‘정책 주색 유지’ 시험은 이 제안의 비지도 브랜드 도입과 충돌할 수 있다. 전역 기본값과 지도 값을 그대로 두면서 **비지도 범위의 기대값**을 추가하는 방향으로 수정한다. 데이터 계산·단계색·지도 토큰 시험을 삭제해 시각 변경을 통과시키지 않는다. UI 구현 후 관련 시험과 `npm test`, `npm run build`를 수행한다. 문서만 작성한 이번 단계에서는 이를 구현 검증으로 실행·주장하지 않는다.

### 완료 조건

- [ ] 일반사용자 종합상황판 → 사업 찾기 → 상세 → 공급 일정에서 바탕·반경·강조색·메타 규격이 이어진다.
- [ ] 카드 제목, 범위, 대표값, 보조값이 분리되어 있으며 같은 유형끼리 좌우·숫자 기준선이 맞는다.
- [ ] 모든 일반사용자 문장은 16px, 보조 정보는 최소 14px다. 정책 표는 14px 밀도를 유지한다.
- [ ] 긴 이름과 지연 사실 문장이 잘리지 않는다. 축약한 사업명은 전체 이름을 접근 가능하게 제공한다.
- [ ] 확인된 0, 자료 없음, 일정 미정, 예정일 경과가 서로 구분된다.
- [ ] 원천·범위·실제/예정·잠정·날짜 불일치가 디자인 간소화 과정에서 사라지지 않는다.
- [ ] 기본 텍스트 4.5:1, 차트·초점 3:1 대비를 양 테마의 실제 사용 면 위에서 확인했다.
- [ ] 키보드로 필터·설명·표 행·서랍을 조작하고 닫은 뒤 초점이 올바른 행으로 돌아간다. 터치 대상은 최소 44px다.
- [ ] 200% 확대 및 390px 폭에서 제목·필터가 겹치지 않고 문서 가로 스크롤이 없다.
- [ ] 다크 모드 첫 진입·클라이언트 이동에서 기본 남색 테마가 순간 노출되지 않는다.
- [ ] 인쇄에서 흰 바탕·텍스트·범위·출처·표 헤더가 읽히고 큰 요약 면이 잉크 덩어리로 출력되지 않는다.
- [ ] `/map`과 내장 지도의 면색·레이블·선택·범례·크기·동작은 변경 전 캡처와 같다.
- [ ] 실제 캡처를 포함한 검수 기록, 테스트 결과, 최종 규칙을 `DESIGN.md`에 반영했다.

### 검수 전에 분리해서 확인할 기존 동작

공급 일정에서 `?sido=metro`로 열었는데 저장된 내 동네 `?sido=41&sgg=41360`으로 바뀌는 현상을 관측했다. `components/region/MyAreaDefault.tsx`는 ‘지역 쿼리가 없을 때만’이라는 주석과 달리 컴포넌트 자체에는 해당 가드가 없고, 현재 일정 페이지는 이를 항상 렌더링한다. 명시한 지역을 보존하는 처리를 디자인 이식과 별도 수정 항목으로 관리한다. 이 동작을 두고 지역별 화면 수치가 맞지 않는다고 판단하지 않는다.

정책담당자 종합상황판 최신 지시 카드와 판정 패널은 현재 작업 중인 변경을 포함한다. 화면 구현자는 작업 시작 시 파일 상태를 다시 확인하고, 이번 문서의 예시 숫자나 과거 결정으로 덮어쓰지 않는다.

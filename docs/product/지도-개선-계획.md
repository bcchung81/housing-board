# 지도 개선 계획: '입주중' 오류, 수도권 HOME 표시, 로딩 속도

작성일은 2026-10-14이다. 원인 분석은 코드 읽기와 저장된 응답 9개 법정동, 원장 2026-10을 기준으로 했다. 속도는 운영 `/map`에서 ego lite로 측정했다. 측정 스크립트는 세션 scratchpad의 `map-movein/`과 `map-perf/`에 있다.

## 1. 결론

- **'입주중' 오류는 판정 규칙의 결함이다.** 사용승인 기록이 하나라도 있으면 몇 년이 지났든 '06 입주 단계'로 판정하고, 이 단계를 빠져나오는 조건이 없다. 여기에 허가 후보에 연도 조건이 없어서 2000년대 기존 아파트까지 '공급 사업'으로 그려진다.
  - 허가 응답에서 입주 단계로 잡힌 134건 중 92%는 준공한 지 24개월이 넘었다.
  - 원장의 06 단계 744건 중 실제 입주 기록이 있는 것은 0건이다.
- **사용자가 느끼는 지연의 주원인은 다운로드보다 순서다.** 로딩 막은 지형(DEM)이 도착해야 걷히는데, 지형 요청은 스타일을 다 읽은 뒤에야 시작한다(3.3초에 시작해 약 1초 걸림). 지형 요청이 실패하면 막이 영원히 걷히지 않는다.
- **수도권에서 차가운 첫 방문이 가장 느리다.** 번들이 없어서 허가·인프라를 요청 시점에 직렬로 받는데, 서버 캐시가 비어 있으면 6.1초 + 2.3초가 걸린다. 수도권 지도 자료를 덤프에서 미리 계산한 정적 파일로 바꾸면 이 사슬이 통째로 사라진다. 데이터 정제와 속도 개선이 만나는 지점이다.

## 2. '입주중' 오류

**코드 경로(확인)**
- 번들이 없는 지역: `lib/permits.js:56` `isCandidate`는 연도 조건 없이 후보로 잡는다. `lib/permits.js:94-99` `statusOf`는 사용검사가 하나라도 있으면 입주로 판정하고 지난 기간을 보지 않는다. `handlers/v1/permits.js:199-219`는 대장 사용승인이 있으면 입주로 올린다.
- 번들 지역: `tools/regiontools/status.py:72-73`도 같은 규칙이다.
- 표시: `region.js:115`(`moveIn` = 준공 달) → `app.js:28,53`(06 입주) → `app.js:560`(격자) · `app.js:1155`(범례 "입주를 시작했거나 마침") · `app.js:1769`(올림 문구).
- 종합상황판은 같은 '06'을 ⑤준공 칸에 넣는다(`board.js:33`). 그래서 지도와 상황판이 같은 사업을 서로 다르게 읽는다.

**재현 사례**

| 단지 | 위치 | 준공일 | 판정 근거 |
|---|---|---|---|
| 작전동풍림아이원 | 인천 계양 | 2003-01-21 | 허가 사용검사일 |
| 푸른마을 동아 | 서울 성북 | 2003-10-08 | 사용검사일 |

**고칠 규칙(1안, 단계 코드는 그대로 두고 표시 표지만 더한다)**
- 경과 함수 하나를 만들어 지도와 상황판이 함께 쓴다: `settledOf(마지막 실제 준공일, 입주예정월, 기준일)`. **기준(2026-10-14 결정, 데이터 구조로 판단)**:
  - **6개월 이하: 입주 진행**(지금 표시). 실제 입주 기록이 원장에 0건이라 '입주'는 준공(사용승인)과 입주예정월(MOVE_IN PLANNED 1,470건)로만 추정할 수 있다. 입주지정기간은 통상 2개월 남짓이고 자료는 월 단위, 상황판 판정 단위가 6개월(지연 ≥6개월)이므로 6개월로 맞춘다. 입주예정월이 있으면 그 달부터 6개월까지도 입주 진행.
  - **7~24개월: 입주 완료**(흐리게). 상황판 리본·추이 기간(2025-01~) 안이다.
  - **24개월 초과: 기존 단지**(기본 숨김, 보기 칩으로 켬). 상황판 기간 밖이고 원장 '진행 중' 규칙(준공 2025년~)과 같은 경계를 굴러가는 24개월로 맞춘 것이다.
  - 원장 06 단계 744건 실측: 입주 진행 151 · 입주 완료 530 · 기존 단지 62 · 날짜 없음 1.
- 허가 후보에 원장과 같은 '진행 중' 규칙(착공 2018년 이후 또는 준공 2025년 이후)을 적용해 기존 재고를 처음부터 거른다.
- 범례 "입주를 시작했거나 마침"을 '입주 진행'과 '입주 완료' 둘로 나눈다.
- 반대 방향 결함도 함께 고친다. LH 후보는 예정 준공일이 지나도 04 단계에 머문다. 같은 경과 함수로 '예정 경과'를 표시한다.
- 원장 지도 색인 행에 실제 준공 달을 실어 지도와 상황판이 같은 값으로 판정하게 한다.
- 영향: 원장 06 단계 744건 중 592건이 '입주 진행'에서 빠진다(완료 530·기존 62). 상황판 숫자는 바뀌지 않는다(지도 표시만).

**대안**
- 2안: 준공 N년이 지난 후보를 응답에서 아예 뺀다. 단순하지만 이미 발급한 옛 사업 id와 어긋난다.
- 3안: 지도도 06을 ⑤준공으로 보고, ⑥입주는 입주 기록이 있을 때만 쓴다. 두 화면의 해석이 같아지지만 리본의 의미가 바뀐다.

## 3. 수도권 HOME 표시

- 수도권(11·28·41) 사업 점·카드·리본은 원장(데이터 정제 계획 D4의 HOME 행)에서 가져온다. `ledger-map.json`의 시군구 키는 정제 계획 D4를 거치면 저절로 HOME 기준이 된다.
- 수도권의 '허가 응답 기반 사업 그리기'(`/api/v1/permits` 후보)는 끈다. 건물·기존 단지는 배경으로만 그린다. 그렇게 하면 기존 아파트가 사업처럼 보이는 문제가 수도권에서는 구조적으로 사라진다.
- 위치는 HOME의 `block_location` 273건과 `project_location` 194건을 쓴다. 좌표의 근거 상태(REVIEW)는 카드 툴팁에 남긴다.
- 상태는 원장 이벤트와 `projectStates`로 정한다. 허가의 `statusOf`는 쓰지 않는다. 경과 표지는 2절 규칙을 그대로 쓴다.
- 계양 번들(3D 건물)은 배경 레이어로 둔다. 번들 단지와 HOME 사업은 LH 블록 키로 잇는다(6절 결정).

## 4. 로딩 속도

**실측(운영, 캐시 없음)**
- `/map`(계양): 전송 3.56MB, 요청 77건. 구성은 지역 자료 0.99MB, 스크립트·CSS·글꼴 0.85MB, DEM 1.49MB, 타일 0.22MB다. 긴 작업은 합쳐서 0.4~0.65초다.
- `?sgg=` 수도권 열기: 전송 2.3~3.0MB.
  - 서버 캐시가 비어 있으면 `permits` 6.1초 → `infra` 2.3초가 직렬로 이어진다. 데워진 뒤에는 약 60ms다.
- CDN 첫 미스 때: `buildings.json` 1.2초, `maplibre-gl.js` 1.0초, DEM 약 2초.
- 직렬 사슬은 문서 → 스크립트 → `app.js`(초기화에 메인 스레드 0.8~1.2초) → 스타일 → (style.load 뒤) DEM → 첫 idle 순이다.
- 요청을 하나씩 막아 봤다.
  - 지역 자료·원장·공고·외부 타일: 첫 idle에 영향이 없다.
  - DEM: 막으면 60초가 지나도 idle에 닿지 않는다.
- 같은 z14 DEM 타일 6장을 `dem`·`dem-shade`가 두 번 받는다(약 570KB 중복).
- 측정 한계: ego lite 창이 가려진 상태라 렌더가 약 1초 단위로 뭉개져서, 첫 idle은 범위로만 믿을 수 있다(계양 4.4~6.8초). S0에서 기준선을 다시 잡는다.

**개선(기대 효과는 측정 근거 기준, 확정치 아님)**

| 순서 | 개선 | 근거·기대 | 위험 |
|---|---|---|---|
| S0 | 기준선 다시 잡기: 페이지 안에 `performance.mark` 계측(막 걷힘·첫 사업 표시·지형 도착)을 넣고, 가려짐의 영향을 받지 않는 지표(요청 시작·끝, 긴 작업)로 비교 | 지금 첫 idle 측정이 불안정함 | 없음 |
| S1 | **로딩 막 기준을 바꾼다.** 스타일·벡터 타일·사업 자료가 준비되면 막을 걷고, 지형은 뒤에 붙인다. 지형이 실패해도 막이 걷히게 한다 | 지형이 막을 쥐고 있음. 기대 4~5초 → 약 2초 | 낮음(지형이 늦게 솟아오르는 장면이 보일 수 있음) |
| S2 | **DEM 요청을 앞당기고 중복을 없앤다.** 스타일과 함께 지형 소스를 선언하고, `dem`·`dem-shade`를 한 소스로 합친다 | 3.3초 출발 → 앞당김, 570KB·요청 6건 감소 | hillshade가 한 소스로 동작하는지 확인 필요 |
| S3 | **수도권 지도 자료를 정적 파일로 바꾼다.** 덤프에서 시군구별 사업·위치 JSON을 미리 만들어 해시 이름 + CDN 장기 캐시로 둔다. 요청 시점의 `permits`·`infra` 사슬을 없앤다 | 차가운 수도권 6.1 + 2.3초 사슬 제거 | 데이터 정제 계획 D4 뒤에만 가능 |
| S4 | `app.js` 초기화를 쪼갠다. 건물 처리(약 250ms)·그림자·보조 레이어를 첫 화면 뒤로 미룬다 | 메인 스레드 0.8~1.2초 | 중간(레거시 전역 스크립트) |
| S5 | 스크립트 `preload` 병렬화, `app.js` 등에 해시 파일명 + immutable 캐시를 둔다 | 재방문 조건부 요청 10여 건(각 약 20ms), 느린 회선의 직렬 로드 | 낮음 |
| 보류 | `buildings.json`(5.9MB) 분할·벡터 타일화 | 이번 측정에서는 비워도 첫 idle 변화 없음 | — |

**함께 고칠 결함**: `/map?sgg=29200`(광주 광산)을 열면 `/api/v1/resolve`가 400("알 수 없는 시도 코드 29")을 돌려준다. 2026-07 광주·전남 통합(코드 12) 뒤 옛 코드를 받지 못하는 것이다. 옛 코드 29·46은 12로 넘기도록 고친다.

## 6. 결정(2026-10-14)

1. 경과 기준: 입주 진행 ≤6개월, 입주 완료 7~24개월, 기존 단지 >24개월(데이터 구조로 판단, 2절).
2. 기존 단지는 기본 숨김, 보기 칩으로 켠다.
3. 지도의 06 해석은 1안(단계 코드 유지 + 표시 표지).
4. 계양 번들(3D 건물)은 배경으로 유지하고, 사업 표시는 HOME 원장 기준.

## 7. 확인하지 못한 것

- 사용자가 본 '2003년 공공' 단지 실례는 찾지 못했다. 원인은 민간·SH·LH 사례로 확인했다.
- 가려지지 않은 창에서의 정확한 첫 idle 시간, 느린 모바일 회선·CPU 제한 조건은 측정하지 못했다.
- 서버 캐시 미스 상태의 수도권 첫 방문은 서버 단독(curl)으로만 재고, 브라우저에서는 재지 못했다.

# 데이터 수집 계획 (원장 다음 단계 1~4)

`docs/product/데이터셋-스키마.md` 7절의 다음 단계 1~4 를 실행 순서·방법·호출량·저장·성공 기준으로 정리한 것이다. 2026-10-10 사용자가 승인했고 2026-10 기준으로 실행을 마쳤다. 결과는 `schemas/ledger-2026-10/` 에 있다(안내: 그 폴더의 README.md). 2026-11 이후의 수집은 실행하지 않고 8절에 문서로만 남긴다.

수집 작업은 서브에이전트에게 난이도별 모델·effort 로 맡겼다(CLAUDE.md 6절). 포털 파일·지역 표는 sonnet·medium, LH 매핑은 sonnet·medium, 건축HUB 스냅샷은 opus·high, 기관 입력 양식은 sonnet·medium 이다.

## 0. 한눈에

## 1. 지역 표 전국화 (F5 법정동코드)

- **원천**: 공공데이터포털 15123287 `국토교통부_법정동코드`. 열 3개(법정동코드 VARCHAR 25 · 법정동명 VARCHAR 150 · 폐지여부). 조사 기록은 2026-09-29 판·53,387행이고, 포털 목록에 보이는 최근 등록본은 2025-08-05 다 — **받을 때 판 날짜를 확인**한다(2026-07 광주·전남 통합 코드 12xxx 가 있어야 한다).
- **방법**: ego lite(백그라운드)로 상세 페이지의 '다운로드'를 누른다. 로그인이 필요하면 사용자에게 넘긴다. 원본은 `schemas/ledger-2026-10/raw/legal-dong/` 에 보관한다(판마다 새 파일, 덮어쓰지 않음).
- **원장 반영**: 존재 행만 areas 로 — 코드 구조로 단계를 정한다(앞 2자리 시도 · 5자리 시군구(일반구 포함, 예 41130 성남시·41131 수정구) · 10자리 법정동(읍면동·리)). 이름은 전체 이름에서 상위 이름을 뺀 끝부분. 폐지 행은 원본 파일에만 둔다(옛 코드 조회용).
- **통합 코드가 없을 때**: 12xxx 만 행정표준코드 API(`lib/stan.js` 이름 검색)로 채운다.
- **2026-10 결과**: `국토교통부_법정동코드_20260929.csv`(2026-09-29 판, 2,471,662바이트, CP949, CRLF)를 로그인 없이 받았다. 53,387행, 존재 20,560 · 폐지 32,827. 2026-07 광주·전남 통합 코드(12, 시군구 27개)가 있다. 세종은 시도 행(36)이 없고 SGG 36110 만 있어 통계누리의 36 으로 채운다. 존재 행 단계는 SIDO 15 · SGG 269 · BJD 20,276 이다. BJD 중 리(뒤 2자리가 00 아님) 15,209 는 건축HUB 조회 단위의 리 수와 같다. 동 등(뒤 2자리 00) 5,067 이 건축HUB 동 3,656 보다 1,411 많은 것은 읍·면 자체 행으로 보인다(전국 읍·면 약 1,410). 원장 areas 는 20,562행이다.
- **성공 기준(시험)**: areas 행 수 = 파일의 존재 행 수 · 레지스트리 5개 시군구 이름이 지금 SGG 표(`lib/board/data.ts`)와 같음 · 법정동 수가 건축HUB 조회 단위(동 3,656 + 리 15,209, 데이터설계 정리본)와 맞음 · 원장 검증 통과.

## 2. LH 블록 시군구 매핑

- **입력**: LH 준공예정 351행 = 278 지구·블록. 위치 글자에서 '시도 시군구(일반구)'를 정규식으로 꺼내면 270건(고유 이름 108개), 못 꺼낸 8건 = 세종 7건(시군구 칸 없음) + 끝에 공백 없는 '경기도 파주시' 1건.
- **대조 순서**: ① 1의 지역 표와 전체 이름 일치 ② 예외 규칙 — 세종은 36110, 옛 이름 '광주광역시·전라남도'(7블록, LH 파일 기준일 2026-01-27 이 통합 전)는 '전남광주통합특별시'로 바꿔 대조 ③ 남은 것만 행정표준코드 API(최대 108회) ④ 그래도 남으면 검토 목록.
- **덤**: 위치 글자의 동 이름(예 창곡동)으로 법정동 10자리도 찾아 project_locations 에 '법정동만 아는 행'(필지 없음)으로 넣는다. 지도 위치는 여전히 '위치 미연결'.
- **같은 사업**: 계양 5블록(A2·A3·A6·A9·A10)은 기존 번들 사업 id 를 `local_project_id` 로 준다(공통규격 v1.4 변환에서 확인한 짝).
- **남는 것**: `schemas/ledger-2026-10/mappings/lh-block-sgg.json` — `[{ district, block, sgg_code, sgg_name, bjd_code, method, local_project_id? }]`(method = 이름 일치·예외 규칙·API·수작업). 변환기 `--lh-sgg` 가 바로 읽는다(후보 id 계산까지, 레지스트리는 그대로).
- **발급은 따로 승인**: 레지스트리에 약 273건을 발급하면 사업 화면이 77 → 약 350건이 되고 우리 동네·사업 상세에 LH 블록이 나온다. `scripts/issue-projects.js` 에 LH 입력을 더해 발급한다(지금은 `--bjd`·`--region` 만 받음).
- **2026-10 결과**: 278 지구·블록 모두 시군구를 찾았다. method 별로 NAME 254 · RULE_SEJONG 7 · RULE_MERGED_SIDO 7(광주광역시 1 + 전라남도 6 → 전남광주통합특별시) · RULE_REORGANIZED_SGG 10 · UNRESOLVED 0 이다. RULE_REORGANIZED_SGG 는 2026-07 인천 개편 때문이다. 서구·중구가 사라져, 동 이름으로 가정동·석남동 → 서해구 28275, 당하동 → 검단구 28290, 중산동 → 영종구 28155 를 찾았다. 법정동까지 찾은 것은 255건이다. 행정표준코드 API 는 2회 불렀고 0행이었다. 계양 5블록(A2·A3·A6·A9·A10)은 기존 사업 PRJ-28245-0005·0004·0001·0003·0006 에 붙였다. 다른 번들과 같은 블록 후보는 0건이다. 명령은 `node tools/ledger/map-lh.js [--api]`. 발급은 하지 않았다: LH 후보 273건의 id 는 발급 전 임시값이고, 화면·레지스트리는 그대로(사업 77건)다.
- **성공 기준**: 278행 모두 시군구가 있거나 검토 사유가 있음 · 모든 sgg_code 가 areas 에 있음 · 계양 5블록은 기존 id · 변환 검토 목록의 SGG_UNRESOLVED 가 그만큼 줄고 원장 검증 통과.

## 3. 일정 월 스냅샷

- **무엇을 찍나(지금 원장 범위)**:
  - 건축HUB 사업 55건: 예정일(`stcnsSchedDay` 착공예정·`useInsptSchedDay` 사용검사예정)과 실제일(`apprvDay`·`stcnsDay`·`useInsptDay`). 지금 연결된 기본개요 오퍼레이션(`getHpBasisOulnInfo`)에 있고 `lib/permits.js` 가 이미 읽는다. 사업이 걸친 법정동이 4곳이라 **월 4~10호출**(하루 1만 중).
  - 지역 번들 22단지: 공정율·착공·준공·입주 시기. 계양은 LH 청약플러스 공사현황을 사람이 받아 번들을 고친 뒤 찍는다.
  - LH 준공예정: 연간 파일이라 **매달 다시 찍지 않고 받은 판본을 모두 보관하는 것이 곧 이력**이다. 새 판이 나오면 그 판을 스냅샷에 넣는다. 월 스냅샷이 꼭 필요한 것은 현재값만 주는 API 원천(건축HUB)이다.
- **관측 월**: 스냅샷의 `observed_month` 는 **찍은 달**이다(원천 기준일은 sources.data_as_of). 지금 변환기는 원천 기준일의 달을 넣고 있어 스냅샷 도구를 만들 때 고친다.
- **당초·변경·현재**: 스냅샷 행은 늘 CURRENT. BASELINE 은 기관 입력의 당초 일정, 없으면 첫 관측 CURRENT 를 화면에서 '첫 관측 기준'으로 표시해 임시 당초로 쓴다. REVISED 는 기관 입력의 승인된 변경. 지연은 둘로 나눠 센다 — ① **예정일 경과**(오늘 > 현재 예정, 실제 기록 없음): 첫 스냅샷부터 ② **당초 대비 지연 개월**(현재 − 당초): 둘째 달부터(기관 입력이 있으면 바로).
- **저장**: `schemas/ledger-<YYYY-MM>/snapshot/hub-events.json` + `manifest.json`(찍은 시각, 원천별 기준일, 호출 수, 행 수). 지난 달 파일은 다시 쓰지 않는다(같은 달 재실행만 덮어쓰고 결과가 같아야 함). 용량은 지금 범위에서 월 약 70 KB(현재 변환 222행이 72 KB), 연 1 MB 안팎. 전국 원장으로 넓혀 수십 MB 가 되면 DB 로 옮긴다.
- **실행**: 서버리스에 쓰기 저장소가 없고(스펙 9.1.1) 저장소에 자동 실행(.github/workflows)이 없다. 매달 같은 주에 로컬에서 `node tools/ledger/snapshot.js --month YYYY-MM [--offline]` 실행 → 검증 → 커밋·배포로 시작하고, 두세 달 안정되면 GitHub Actions 월 실행(키는 저장소 비밀값)을 정한다. **한 달을 빠뜨리면 그 달 이력은 영원히 비므로 첫 스냅샷은 2026-10 안에 찍는다.**
- **LH 함정**: LH 파일 기준일은 2026-01-27, 예정일은 2026-01-31 부터라 이미 지난 블록이 있다. 그 사이 준공됐는지 알 실제 기록이 없다(LH 블록은 필지가 없어 건물대장 대조 불가). **새 판을 받기 전에는 LH 의 '예정일 경과'를 지연으로 보이지 않는다.**
- **성공 기준**: 같은 달 재실행 결과 동일 · 지난 달 파일 불변(시험) · '예정일 경과' 판정이 아래 정의와 같고 `lib/permits.js` overdue 판정 사업을 모두 포함하며 차이가 아래 두 가지로 설명됨 · 스냅샷 행이 원장 검증 통과.
  - **예정일 경과 정의**: 현재 예정(CURRENT)의 기간 끝(일·월말·연말)이 기준일보다 앞이고, 같은 종류의 실제(ACTUAL) 기록이 없고, 사업 단계가 아직 그 단계(착공 04 · 준공 06)에 못 미친 건축HUB 사업.
  - **분류 기준(2026-10-10 결정)**: 경과 개월 = 기준일과 현재 예정의 기간 끝 사이 꽉 찬 달 수(기준일의 일이 끝 날짜의 일보다 작으면 1을 뺀다). 사업마다 가장 큰 값으로 지연 6개월 이상 · 주의 1개월 이상 6개월 미만 · 정상 그 밖(경과 없음 포함). 2026-10-10 판정 대상 54건(발급 사업 중 착공·준공 현재 예정이 있는 사업) = 정상 45 · 주의 2 · 지연 7(`tools/ledger/board.js`).
  - **원천별 예외(2026-10-11 결정)**: 건축HUB 대용량 후보는 착공 실제일 기록이 약 7% 뿐이라 착공 예정 경과를 정상·주의·지연에서 빼고 사용검사(준공) 예정 경과만 판정한다. 뺀 쌍은 `judgment.excludedStartOverdue`(2,407쌍·1,363,918호)로 따로 센다. 발급 사업(건축HUB 스냅샷)은 착공·준공 둘 다 판정한다. 이 기준 판정 3,411건 = 정상 2,757 · 주의 134 · 지연 520.
  - **차이 두 가지**: ① lib/permits.js 는 상태마다 한 종류만 본다('계획'이면 착공만). ② 필지가 없는 블록 단위 허가(감일 0038·0041)는 판정하지 않는다.
  - 단계 조건이 없으면 18개 사업이 된다. 감일 블록 9건은 건물대장으로 준공(06)을 알아냈지만 건축HUB 에는 실제 기록이 없어, 지연으로 잘못 잡힌다.
- **2026-10 결과**: 레지스트리 건축HUB 사업 55건, 관리번호 58개를 모두 대조해 209행을 만들었다(`snapshot/hub-events.json`·`manifest.json`). 건축HUB 기본개요 호출은 10번(10쪽)에 레코드 844건이고 인증키는 저장하지 않았다. 온라인 실행은 한국시간 이번 달만 받는다.

## 4. 기관 입력 CSV 양식

- **전제**: 실제 기관에서 받는 경로는 없다(기획서: PoC 는 가상 기관 입력). 그래서 양식·안내·가져오기 도구와 **가상 예시**를 만들고, 가상 예시는 실데이터와 표지로 가른다(종합상황판 SAMPLE 표지와 같은 원칙, 결정 11).
- **양식(UTF-8 BOM CSV, 머리글 = 원장 열 이름 — 공통규격 v1.4 와 같은 형식, 엑셀에서 열림)**:

| 파일 | 원장 표 | 열 |
|---|---|---|
| 기관_사업.csv | projects (+ identifiers MANUAL) | 기존 사업이면 local_project_id, 새 사업이면 project_name·sgg_code·agency_id·stage_code |
| 기관_일정.csv | events | local_project_id · event_type · plan_basis(BASELINE·REVISED) · event_date 또는 event_month · change_reason · change_note · 승인일 |
| 기관_계획물량.csv | units(AGENCY_PLAN) | local_project_id · housing_type · unit_count · reference_period |
| 정책.csv · 프로그램.csv · 연결.csv | policies · programs · links | v1.4 열 그대로 |

- **가져오기 도구**: `tools/ledger/import-agency.js` — CSV → 원장 행 → 검증(스키마·참조) → 거부 행과 사유 출력. 통과한 행만 보관한다. 양식과 가상 예시는 `schemas/ledger-2026-10/agency/` 에 둔다.
- **2026-10 결과**: 양식 6종(`agency/templates/`: 기관_사업 · 기관_일정 · 기관_계획물량 · 정책 · 프로그램 · 연결, UTF-8 BOM, source_ref·review_status 는 도구가 채움)과 `agency/README.md`, 가상 예시 `agency/demo/`('[가상]' CSV 6종 + rows.json)를 만들었다. 가상 예시가 만든 행은 sources 1 · projects 1(임시 id PRJ-28245-0007, issued_at null) · identifiers 2 · events 6 · units 4 · policies 1 · programs 1 · links 4 이고 모두 is_demo 원천을 가리킨다. 기준 표에는 합치지 않았다. 명령은 `node tools/ledger/import-agency.js --dir <폴더> --agency <id> --received YYYY-MM-DD [--demo] [--out <파일>]`. 임시 id 는 레지스트리 counters 와 base 사업 id 중 큰 쪽의 다음 번호다. base 는 LH 후보가 없는 변환 결과이므로, LH 후보가 있는 시군구에 새 사업을 넣을 때는 기준 표를 base 로 써야 번호가 겹치지 않는다.
- **스키마의 빈 곳**: 기관을 가리키는 source_owner·id_issuer 값이 없다(임시로 'AGENCY'·'HOUSING_WAVE'). 같은 입력을 다시 보내면 계획 물량 행이 겹친다. 원천(source_ref = 받은 묶음)이 같은 것 중 최신 묶음만 쓰는 규칙이 필요하다.
- **성공 기준**: 빈 양식과 가상 예시가 검증을 통과 · 없는 사업·실제일에 당초 구분·허용값 밖 사유를 거부(시험) · 가상 예시의 모든 행이 is_demo 원천을 가리킴.

## 5. 스키마 보강 (3·4 전에 한 번에)

| 보강 | 이유 |
|---|---|
| events.event_year | 건축HUB 예정일이 'YYYY'(연도만)로 오기도 해 일·월 칸에 담을 수 없다 |
| events.change_reason · change_note | 기관 입력의 지연 사유(기획서 시나리오 A: 인허가·사업승인·착공·기타) |
| sources.is_demo | 가상 기관 입력을 실데이터와 가르는 표지(원천 단위라 행마다 칸을 늘리지 않음, v1.4 로 낼 때 is_demo 를 여기서 채움) |
| 변환기 observed_month 규칙 | 스냅샷에서는 찍은 달 |

## 6. 이 계획 밖이지만 종합상황판을 채우는 단계

1~4 를 다 해도 판정 대상은 원장에 있는 사업(건축HUB 55 + 번들 22 + LH 약 273)뿐이다. 전국 판정을 채우는 단계는 8절 6번에 모았다.

## 7. 결정 (2026-10-10 승인)

사용자가 다섯 결정을 모두 추천안대로 승인했다.

1. 순서: 지역 표(1) → LH 매핑(2), 스냅샷(3)·양식(4)은 병렬.
2. LH 발급(레지스트리 약 273건 추가, 화면 변화)은 매핑 결과를 본 뒤 따로 승인.
3. 스냅샷은 매달 로컬 실행으로 2026-10 에 시작, 자동화는 두세 달 뒤 결정.
4. 5절의 스키마 보강 4가지.
5. 가상 기관 입력은 sources.is_demo 로 표지.

추가로, 2026-10 기준으로 한 번 맞추고 2026-11 이후의 수집은 실행하지 않고 문서로만 남기기로 했다. 이번 데이터는 `schemas/ledger-2026-10/` 에 둔다(계획서에 적었던 `data/raw/stan`·`data/ledger/...` 경로를 이 폴더로 바꿨다). `.vercelignore` 가 `schemas/` 를 빼므로 배포에는 실리지 않는다.

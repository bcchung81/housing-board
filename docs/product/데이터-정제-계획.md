# 데이터 정제 계획: 수도권 HOME 덤프 정본

작성일은 2026-10-14다. 이 문서는 `HOME-데이터-이관-계획.md`(선별 이관, 겹치면 병합)을 대체한다. 덤프 측정값은 그 문서에서 그대로 가져온다.

## 0. 요구사항(사용자 2026-10-14)

1. 사업–정책 연결 308건은 팀원이 다시 매칭해서 다시 덤프한다.
2. 종합상황판은 전국을 보인다. 서울·경기·인천은 팀원이 다시 덤프한 자료를 기준으로 한다. (2026-10-20 폐기: 수도권만 싣는다. 전국 자료는 원장·Supabase 에 남기지 않는다)
3. 주 1회 자동 갱신은 없앤다. 데이터가 안정되면 갱신 로직을 다시 짠다.
4. 서울·경기·인천은 덤프를 따른다. 덤프를 다시 넣어도 구조가 깨지지 않도록 Supabase를 정제한다.
5. 지도의 수도권 표시는 HOME 자료를 쓴다. '입주중' 오류는 `지도-개선-계획.md`에서 다룬다.

## 1. 결론

- **경계는 시도 단위로 나눈다.** 시도 코드 11(서울)·28(인천)·41(경기)의 사업·일정·호수·위치·연결은 HOME 덤프만 정본으로 쓴다. 나머지 시도는 싣지 않는다(2026-10-19·20 결정: 수도권만. 당초에는 지금 원천을 그대로 쓰기로 했다).
- **교체는 변환 끝의 한 지점에서 한다.** `convert()` 결과에서 수도권 행을 걷어 내고 HOME 행을 넣는 함수(`replaceSido`) 하나로 처리한다. 수도권 밖 행은 `--sidos 11,28,41` 로 아예 뺀다. 종합상황판 집계(`board.js`)는 원장 표만으로 시도별 값과 수도권 합계를 함께 만들기 때문에, 표가 맞으면 수도권 합계도 저절로 맞는다.
- **재덤프에 견디는 조건은 네 가지다.**
  - ① 덤프 판마다 원본층을 따로 남긴다.
  - ② HOME id와 우리 사업 id의 대응표를 계속 쌓는다.
  - ③ Supabase 적재가 이번 판에 없는 행을 지우게 고친다. 지금은 남는다.
  - ④ 같은 덤프를 두 번 넣었을 때 결과가 같은지 시험으로 고정한다.
- **주 1회 갱신 예약은 가장 먼저 끈다.** 이 갱신은 봇이 main에 직접 커밋하고 적재까지 한다. 켜 둔 채로 수도권을 바꾸면 건축HUB 값으로 다시 덮어쓴다.

## 3. 목표 구조

```
덤프 판(home.dump, SHA)                 지금 원천(건축HUB·LH·공고·통계누리)
   │ pg_restore 스트림(Docker·로컬 DB 없음)        │
   ▼                                              ▼
raw/home/<덤프시각>/*.jsonl.gz + manifest   raw/* (그대로)
   │ home-source.js: 21 kind 현재 판 → 원장 행     │ convert.js 원천별 루프
   └──────────────► replaceSido(t, home, ['11','28','41']) ◄──┘
                        │  수도권: 기존 원천 행 제거 + HOME 행
                        │  id: mappings/home-ids.json(누적) → PRJ-<시군구>-<일련>
                        ▼
              tables/*.json → board.js(대체 거르기 포함) → ledger-board·ledger-map
                        ▼
              supabase-load.js → publish_run(이번 판에 없는 사업 정리)
```

## 6. 결정(사용자 2026-10-14)

1. **월 수집 예약(`ledger-collect`)도 제거**한다(수동 실행은 남김). (비수도권 건축HUB 새 판은 2026-10-20 폐기: 수도권만 싣는다.)
2. **수도권 통계누리 실적은 유지**한다(덤프 statistic 은 대조 시험만).
3. **수도권 발급 id 는 HOME 사업으로 대체**한다. 성북·하남·계양 레지스트리 사업은 대응 HOME 사업으로 `superseded_by`, 옛 주소는 새 사업으로 넘긴다. 대응이 없는 사업은 대체 대상 없이 숨김(id 는 남겨 링크가 '대체됨' 안내로 열림).
4. HOME 에 없는 수도권 사업(건축HUB 대용량 후보 등)은 버린다(요구 2·4).
5. 덤프 전달은 `~/Downloads/HOME_DB_<시각>/` 폴더 그대로 받고, 판 이름은 덤프 시각(`manifest.json snapshot_at`)으로 한다.
6. **(2026-10-20) 전국 잔존 자료를 제거한다.** 원장의 areas 비수도권 17,561행·stat_facts 비수도권 13,440행을 지우고(Supabase 포함) 수도권만 남긴다. 옛 HOME 판 원본 폴더(`raw/home/20261013T140241Z`·`20261014T102506Z`)는 로컬에서 지운다(Storage 에는 되돌리기 근거로 남긴다). 새 판은 2026-10-20 덤프(`20261019T212247Z`)다.

- 재매칭하면 HOME id(HPR_)가 유지되는지 모른다. 여러 키로 잇는 방식으로 위험을 줄였지만, D5 ⑤에서 확인해야 한다.

- 덤프 밖 원문 파일(PDF·HTML)은 전달되지 않았다. 경로와 해시만 있다.

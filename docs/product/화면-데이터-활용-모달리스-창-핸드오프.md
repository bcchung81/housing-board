# 화면 데이터 활용·모달리스 창 핸드오프

작성일: 2026-10-19(구현 반영 2026-10-20) · 대상: 프런트엔드·데이터 변환 구현자, 화면 검수 담당 · 상태: **5절 창(W1·W2·W3)·K1(/citizen 시트)·지도 '전체 n' 구현 완료(미커밋, 11·12절)**, 4절 데이터 제안·W4 는 계획 · 교차검증: codex·antigravity 완료(10절)

이 문서는 세 가지를 넘긴다. (1) 가지고 있는데 화면에 쓰지 않는 중요한 데이터, (2) 일반사용자·정책담당자 관점에서 새로 필요한 데이터, (3) 오른쪽 서랍으로 열리는 화면을 모달리스 창(뒤 화면을 막지 않는 떠 있는 창)으로 바꿀 대상과 규격. 숫자는 2026-10-19 작업 트리에서 직접 세어 확인한 값이다(9절 근거).

## 0. 한 장 요약

- **쓰지 않는 데이터 가운데 중요한 것은 다섯 가지다.**
  - ① HOME 10-14 판 **관리 목표 일정**: `execution_schedule` 1,182행이 화면 사업 148곳에 이어진다. 그런데 화면은 "당초 일정 없음"만 적는다.
  - ② **LH 공고문 근거**: `document_evidence` 234행에 입주월 129행, 공급 유형 128행, 원문 주소 234행이 있다. 지금은 정책 진행 계산에만 쓴다.
  - ③ **사업 ↔ 공고 연결**: 36곳이 연결돼 있는데, 일반사용자 상세는 청약홈 **첫 화면**으로만 보낸다.
  - ④ **검토 대기 기록**: 15건과 순서 이상 규칙 11개(HOME 사업 236곳)가 있다. 화면에 없어서 데이터를 얼마나 믿을지 판단할 길이 없다.
  - ⑤ **'검토 중' 정책 연결** 98곳을 숫자 옆에 표시하지 않는다.
- **새로 확보할 데이터**:
  - 정책담당자: 지연 사유와 당초·변경 일정. 원천이 없어 기관 입력으로 받아야 한다.
  - 일반사용자: 입주 예정월(262곳 중 202곳에 없음), 주택형·분양가·임대료, 수도권 기반시설.
- **모달리스 창으로 바꿀 대상**:
  - 사업 상세 서랍 하나: `components/projects/Drawer.tsx`. `/projects` 와 `/citizen/projects` 가 함께 쓴다.
  - **다른 화면에서 사업을 누르면 `/projects?id=` 로 페이지를 옮기는 진입점 9곳**(5절 W2).
  - 지금 서랍에도 막과 포커스 가둠은 없다(`aria-modal="false"`). 문제는 세 가지다. 폭 60%를 덮고, 한 번에 하나만 열리고, 다른 화면에서는 열 수 없다.
- **바꾸지 않는 것**:
  - `/citizen` 정적 시트: 완전 모달이고 모바일 우선이라 보류한다.
  - 지도의 위치 미확보 말풍선, '전체 n' 덮개, 하단 시트.
  - ⓘ·칩 메뉴·툴팁.
  - 관점 전환 링크(`PublicDetail.tsx:91` '정책담당자 화면에서 보기').
  - 휴대폰 폭(≤900px)에서는 모든 창을 지금처럼 전면·아래 시트로 둔다.
- **결정할 것 8가지는 7절에 모았다.** 커밋·적재·배포는 사용자 승인 뒤에 한다.

## 1. 범위와 점검 방법

| 화면 | 경로 | 점검 |
|---|---|---|
| 정책담당자 | `/`, `/projects`(`?id=`·`?cand=`·`?print=1`), `/region`, `/sources`, `/month/[id]`, `/agency/[id]`, `/map`(개요·상세) | 데이터 출처·표시 필드·서랍·링크 |
| 일반사용자 | `/citizen`(정적 HTML), `/citizen/projects`(`?id=`), `/citizen/schedule` | 같음 |
| 데이터 | 원장 `schemas/ledger-2026-10/tables/*.json`, HOME 덤프 `schemas/ledger-2026-10/raw/home/20261014T102506Z/*.jsonl.gz`, 화면 요약본 `data/board/*.json`, Supabase `api.*`, `/api/v1/*` | 행 수·빈 필드·화면 참조 |

- 방법: 코드 읽기와 `grep` 으로 화면 참조를 찾고, 행 수·빈 필드는 `node`·`gzcat` 으로 직접 셌다. 브라우저 확인은 하지 않았다(화면 확인은 사용자가 직접 — 메모 규칙).
- 데이터 흐름: 원장 표 → `tools/ledger/*.js` → `data/board/*.json`(요약본) → 화면.
  - **화면은 원장 표를 직접 읽지 않는다.** 그래서 요약 단계에서 빠진 필드는 화면에 나올 수 없다.
  - 화면이 Supabase 에서 읽는 것은 `api.board`·`api.screens` 뿐이다.
  - 사업 목록·상세·지역·지도 자료는 빌드 때 묶인 JSON 이다.

### 창 규격(공용 부품 `FloatingWindow` — 이름은 구현자 판단)

- **폭 >900px**: 떠 있는 창.
  - 위치·크기: 첫 위치는 지금 서랍 자리(오른쪽 위, 상단 메뉴 아래). 기본 폭 560px(최소 400, 최대 화면의 60%). 높이는 내용에 맞추되 최대 화면 − 96px, 넘치면 안쪽 스크롤.
  - 조작: 머리 줄을 끌어 옮기고, 오른쪽 아래 모서리로 크기를 바꾼다. 접기(머리만 남김)·닫기 단추를 둔다.
  - 배치: 새 창은 앞 창에서 24px 어긋나게 연다. 창이 화면 밖으로 나가면 열 때와 화면 크기가 바뀔 때 화면 안으로 되돌린다.
- **폭 ≤900px**: 지금처럼 전면 시트(`mobile:w-full`) 하나만 연다. 다른 사업을 열면 내용만 바뀐다. 끌기·크기 조절은 없다.
- **창 상태 규칙**(창 목록은 클라이언트 상태, 맨 위 창 = 활성 창):

2026-10-20 구현에서 아래 표로 정했다. 처음 계획(열 때마다 기록을 쌓고, 뒤로가기는 활성 창만 닫기)은 쓰지 않았다. 그 방식은 닫은 창이 뒤로가기로 되살아나고, Next 내부 기록 상태와 엉킬 위험이 있었다. 대신 옛 서랍의 '기준 기록 하나' 방식을 창 여러 개로 넓혔다. 판정 함수는 `components/windows/nav.ts` 의 `navStep`·`popAction`·`place` 다.

| 동작 | 결과 |
|---|---|
| 첫 창 열기(창 0 → 1) | 새 창이 맨 위로 온다. 지금 주소에 `?id=`(후보면 `?cand=`)를 붙이고 기록을 하나 쌓는다(`pushState`) |
| 창이 있는데 사업을 더 엶 | 새 창이 맨 위로 온다. 주소는 `replaceState`(기록이 쌓이지 않는다) |
| 이미 열린 사업을 다시 누름 | 새로 열지 않고 그 창을 맨 위로 올린다. 주소는 `replaceState` |
| 다른 창을 누름 | 그 창이 맨 위로 온다. 주소는 `replaceState` |
| 활성 창 닫기(×·Esc) | 다음 맨 위 사업 창의 id 로 주소를 바꾼다(`replaceState`) |
| 마지막 창 닫기 | 기준 기록을 쌓았으면 `history.back()`, 주소로 바로 열었으면 `replaceState` 로 `id`·`cand` 를 뺀다 |
| 뒤로가기 | 주소에 `id`·`cand` 가 없어지므로 **창을 모두 닫는다**. 앞으로가기 등으로 주소에 사업이 있으면 그 창을 맨 위로(없으면 연다) |
| 창 수 상한(정책 화면 3, 일반사용자 1) 넘음 | 가장 오래된(맨 아래) 창을 닫는다. 일반사용자 화면은 내용이 바뀐다 |
| 새로고침·주소 공유 | 주소의 창 하나만 열린 채 온다(`/projects`·`/citizen/projects` 는 서버가 첫 창을 그려 깜박임이 없다. 다른 화면은 장착 뒤 API 로 연다) |
| 인쇄 보기(`?print=1`) | 열린 창을 모두 닫고 창을 열지 않는다 |

- **접근성**:
  - 창마다 `role="dialog" aria-modal="false"` 를 단다. 제목과 안쪽 구역(`pd-sched`·`drawer-title` 등)의 `id` 는 창마다 고유하게 만든다(`useId`).
  - 열면 제목에 초점을 두고, 닫으면 연 요소로 초점을 돌린다. Esc 는 **맨 위(활성) 창**만 닫는다. 창 안 ⓘ·칩 메뉴가 열려 있으면 그것부터 닫는다.
  - 지금 `Drawer.tsx:64-67` 의 전역 `document.querySelector` 와 창마다의 `keydown` 리스너는 쓰지 않는다. 키 처리는 창 관리자 하나가 맡는다.
- **움직임·인쇄**: 움직임 줄이기 설정이면 열림 전이를 끈다. `print:hidden` 을 유지하고, `?print=1` 에서는 창 자료를 읽지 않는다(지금과 같음).
- **모양**: `--popover` 면, `--shadow-pop`, 카드 반경을 쓴다. 창은 '화면 가장자리 구조 판' 예외가 아니므로 모서리를 둥글게 한다. DESIGN.md 에 '떠 있는 창' 규칙을 새로 적는다(CLAUDE.md 9절 — 사용자 확인 뒤 같은 작업에서).

### 구조 변경(가장 큰 비용)

지금 상세는 `/projects` 서버가 `getProjectDrawer(id)` 로 그려 페이지에 끼운다(`projects/page.tsx:51,83`). 다른 화면에서 그 자리에서 열려면 상세 자료를 따로 받아야 한다.

- **상세 API**: `GET /api/v1/project/{id}`
  - 응답은 `{ kind: 'detail' | 'candidate' | 'hidden' | 'replaced', id, canonical, row, detail, sources, dataAsOf }` 꼴이다. `getProjectDrawer` 의 숨김·옛 id·대표 사업 처리(`lib/board/projects-index.ts:41-58`)와 후보 행(`candidateOf`, `projects-view.ts:449`)을 그대로 재사용한다.
  - 응답 필드는 **창에 보이는 것만** 허용 목록으로 내보낸다. 건축HUB 관리번호(`pks`, 공개 범위 미결 — `projects-view.ts:19`)·`bundles`·`bjd` 는 넣지 않는다. 지금 상세 자료는 서버 전용이라, HTTP 로 내보내는 것은 새 공개 경로다(결정 ⑧).
  - 없는 id 는 404 를 돌려준다. 응답에 자료 판(`dataAsOf`)을 싣는다. 응답 순서가 뒤바뀌면 늦게 온 응답은 버린다.
- **창 관리자**: 대시보드 레이아웃에 클라이언트 섬 하나를 두고 창 목록·키·주소를 맡긴다. `ProjectDetail`·`PublicDetail`·`Candidate` 는 클라이언트에서 그린다. 서버 전용 모듈을 쓰지 않는지, `Candidate` 의 `stageHref` 함수 인자를 직렬화할 수 있는 값으로 바꿀 수 있는지를 먼저 확인한다.
- **지도(`/map`)**: 지도는 정적 JS(`assets/js/app.js`)라 React 부품을 직접 부를 수 없다. 지도 페이지도 Next 경로(`app/(map)/map/page.tsx`, `MapIsland.tsx`)이므로 같은 창 관리자 섬을 올린다. `app.js` 의 사업 링크는 클릭을 가로채 `window.dispatchEvent(new CustomEvent('project:open', { detail: { id } }))` 로 연다. 보조 키를 누른 클릭과 가운데 단추는 가로채지 않는다. 지도 화면에 창이 하나 이상 떠 있을 때는 카드 배치(`fitCard`)가 창을 피해야 한다.
- 대안으로 Next 가로채기·병렬 경로(`@modal`)도 있다. 그러나 창 하나에는 맞지만 여러 개나 다른 루트 레이아웃(`/map`)에는 맞지 않아 채택하지 않는다.

## 2. 3D 그래프 개선 설계

### 정면 시점과 깊이 표현

- **정면 원근 카메라를 선택한다.**
  - 정사영은 층별 수치 정렬에 유리하다.
  - 다만 완전 정면에서는 z 간격과 평행한 옆벽이 화면에서 거의 드러나지 않는다.
  - 원근은 카메라를 기울이지 않아도 가장자리 옆면과 깊이를 표현할 수 있다.
  - 층별 원근 배율 차이는 앞면 좌표 보정으로 제거한다.

- 카메라 시작값:
  - `VIEW.W=10`, `VIEW.H=4`, `VIEW.DZ=0.32` 유지.
  - `VIEW.fov=24°` 제안.
  - `tilt=π/2`, `turn=0`.
  - 카메라 up은 `[0,1,0]`.
  - 차트 중심에서 z축 방향으로만 떨어진다.
  - 회전·이동·확대 컨트롤은 추가하지 않는다.

- 공통 계산 함수 제안:
  - `plotRect(size, labelMetrics)`: 축 여백을 제외한 그림 영역.
  - `viewFor(size, plot)`: 거리·투영 중심·기준 깊이.
  - `facePoint(p, view)`: 앞면의 원근 배율 보정.
  - `toScreen(p, size, view)`: 렌더 카메라와 같은 투영.
  - `monthAtScreenX(...)`: 그림 영역 기준 월 선택.

- 앞면 좌표 보정:
  - 기준 평면을 `zRef`로 둔다.
  - 카메라는 `zRef+D`에 둔다.
  - 깊이 z의 앞면 좌표에 다음 배율을 적용한다.

  ```text
  q = (D + zRef − z) / D
  x′ = cx + (x − cx) × q
  y′ = cy + (y − cy) × q
  ```

  - 투영 후 같은 월·같은 누적값은 같은 화면 좌표에 놓인다.
  - `stackOf`와 `stripOf`의 논리 좌표는 유지한다.
  - 보정은 렌더 기하를 만들 때 적용한다.
  - 선택 막대·지연 띠·윤곽도 같은 보정을 쓴다.

- 깊이 표현:
  - 단계별 z 간격은 `0.32` 유지.
  - 띠 뒤쪽으로 두께 `0.12`의 옆면 추가.
  - 앞면 데이터 경계는 이동하지 않는다.
  - 옆면은 단계색과 `--rb-lo`를 82:18로 혼합한다.
  - 상단 밝은 면은 단계색과 `--rb-hi`를 90:10으로 혼합한다.
  - 두께·명암은 장식값이다. 호수나 단계 진행량을 뜻하지 않는다.
  - 0호 층에는 가짜 최소 높이를 주지 않는다.
  - 별도 투사 그림자·후처리는 추가하지 않는다. 얇은 옆면과 명암을 먼저 검증한다.

### 축·눈금·기준선과 넘침

- 캔버스는 기존 호스트 전체를 채운다.
- **캔버스 내부**에 그림 영역과 축 영역을 나눈다.
- 초기 내부 여백:
  - 왼쪽: `max(56px, 가장 넓은 세로 눈금+12px)`.
  - 오른쪽: `20px`.
  - 위: `32px`.
  - 아래: `40px`.
  - 전체 글자와 호스트 경계 사이 최소 `6px`.
- 치수는 공통 레이아웃 상수 또는 의미 토큰으로 관리한다.
- 비대칭 여백은 카메라 투영 중심에 반영한다. 카메라를 기울여 맞추지 않는다.
- `fitDistance`의 기존 가로 12%·세로 30% 여유를 실제 픽셀 여백 계산으로 대체한다.

- 가로축:
  - 모든 연도 글자를 같은 화면 y에 놓는다.
  - 첫 글자는 시작 정렬, 마지막 글자는 끝 정렬을 허용한다.
  - 글자 전체 경계를 측정한다.
  - 축선과 글자 사이 간격은 8px 이상.
  - 전체 기간은 연도 눈금 유지.
  - 월별 짧은 눈금, 1월의 긴 눈금을 구분한다.

- 세로축:
  - 모든 눈금 글자의 오른쪽 끝을 같은 화면 x에 맞춘다.
  - `yAxis`에 실제 그림 영역 높이를 전달한다.
  - 48px당 눈금 하나, 2~8개 규칙 유지.
  - `0`은 세로축에 유지한다. 첫 연도와 별도 영역에 배치한다.
  - 단위 `호` 또는 `만 호`를 축 위쪽에 명시한다.

## 5. 시험 계획

### 먼저 실패하는 시험 작성

1. 새 요구를 단언하는 시험을 추가한다.
2. 현재 구현에서 해당 시험이 실패하는지 확인한다.
3. 구현 후 통과시킨다.
4. 기존 계산·대체·키보드 시험은 유지한다.

### 순수 계산 단언

- 정면 카메라의 x·y는 기준 중심과 같다.
- 같은 y의 좌우 점은 같은 화면 y다.
- 같은 x의 상하 점은 같은 화면 x다.
- 보정한 앞면은 깊이가 달라도 같은 월·값에서 같은 화면 좌표다.
- `toScreen`은 실제 `PerspectiveCamera.project`와 일치한다.
- 비대칭 축 여백·크기 변경을 포함한다.
- `monthAtScreenX`는 여백을 제외한다.
- 첫 달·마지막 달·중앙 달이 정확히 선택된다.
- 단계별 `lo`·`hi`·`band`·총량은 기존 2D와 같다.
- 옆면은 앞면의 데이터 경계를 바꾸지 않는다.
- 전부 0인 데이터도 축 계산이 유효하다.
- 토큰 알파와 역할 불투명도가 곱해진다.
- 툴팁 배치는 실측 크기 기준으로 판 안 6px를 지킨다.

### UI·회귀 단언

- 축·툴팁은 Canvas 밖 하나의 DOM 덮개 층이다.
- drei `Html`·개별 React 루트 생성이 없다.
- 툴팁 단계는 2열·3행이며 6개 값이 모두 남는다.
- 2D·3D가 같은 `tipBody`를 사용한다.
- aria 안내에 확대·회전·끌기 설명이 없다.
- `frameloop="demand"`, DPR 상한 2, 동적 import 유지.
- WebGL 불가·줄임 설정·900px 이하 대체 유지.
- 기존 `qa-1021` 완료 항목이 모두 통과한다.
- 정적 정규식 시험은 새 구조에 맞춘다. 기능 단언을 삭제해 통과시키지 않는다.

### 브라우저 경계 단언

- 각 축 글자의 `getBoundingClientRect()` 전체가 캔버스 경계 안이다.
- 각 글자와 캔버스 경계 사이 6px 이상이다.
- 축 글자끼리 교차하지 않는다.
- 연도 글자 기준 y 편차 ≤1 CSS px.
- 세로 눈금 오른쪽 끝 x 편차 ≤1 CSS px.
- 툴팁 전체가 판 안에 들어온다.
- 글자를 숨기거나 잘라 경계 시험을 통과시키지 않는다.

  - 열린 질문: 들어올 해 기준을 유지하며 과거 묶음을 분리할지, 모집 해 기준으로 계산까지 바꿀지.
  - 결정 전까지 구현 보류. 3D 개선 완료와 별도로 추적한다.

- **정면 원근의 수치 왜곡**
  - z 간격만 유지하면 층별 배율이 달라진다.
  - 앞면 보정과 동일 월·값 투영 시험이 필수다.

- **깊이 표현의 한계**
  - 정면에서는 기존 사선 시점보다 옆면이 약하다.
  - 두께·윤곽·명암을 조정한다. 카메라 기울기를 다시 넣지 않는다.

- **투명 면·빗금**
  - 깊이 정렬 오류·겹침·모아레 가능성이 있다.
  - 두 테마와 DPR 1·2에서 확인한다.

- **기존 시험 통과의 의미**
  - 현재 29개 통과는 기존 계약의 정상 여부다.
  - 새 정면 시점·글자 전체 경계·시각 품질의 충족을 뜻하지 않는다.

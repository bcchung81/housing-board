# PoC HOME 개념·데이터 흡수 계획

작성일은 2026-10-13이다. 대상은 [acesharp81/minslab `PoC/10-home`](https://github.com/acesharp81/minslab/tree/main/PoC/10-home)(운영 https://www.minslab.kr/poc/home/, 커밋 21c60b1)이다.

전제(사용자 지시 2026-10-13):
- HOME 화면을 옮기지 않고 새로 만든다.
- HOME에서 가져오는 것은 개념과 데이터(Supabase 이관)뿐이다.
- 메뉴 7개는 유지한다.
- 깔끔한 UI를 목표로 한다.

## 1. 결론

메뉴를 새로 만들지 않아도 된다. 새 상세 경로도 필요 없다. 핵심은 HOME의 **정책별·프로그램별·사업별 추진현황 세 화면을 화면이 아닌 '렌즈'(거르기 칩)로 바꾸는 것**이다. 세 화면은 같은 사업 목록을 다른 묶음으로 본 것이기 때문이다. 나머지 개념도 기존 메뉴 안의 한 자리씩만 차지한다.

## 2. HOME 개념 → 우리 메뉴

| HOME 개념 | 들어갈 자리 | 만드는 것(최소 형태) | 만들지 않는 것 |
|---|---|---|---|
| ① 정책 → 프로그램 → 사업 묶음 | **사업**, 그리고 종합상황판·지도·보고자료가 공유 | 렌즈 칩 `전체 · 9·7 · 1·29 · 8·13 · 프로그램 ▾` (`?policy=` `?program=`) | 정책별·프로그램별 별도 화면, 연결 트리 화면 |
| ② 단계별 목표 대비 확인 | **사업** 요약 띠 | 렌즈를 고르면 단계 분포 자리가 '6단계 목표/확인 막대'로 바뀐다 | 월별 누적 면적 그래프, 일정 민감도 시나리오, 결정 작업 영역 |
| ③ 계획·예정·확인·미확보 구분 | 모든 화면 | 상태 표기 4가지로 통일(3절) | HOME의 7종 범례와 면책 문단 |
| ④ 연도별 공식 실적 | **공급 실적** | 기간 전환 `월별 \| 연도별` 하나. 부분 연도는 옅게, 전년 대비는 두 해 모두 12/12개월일 때만 | 새 탭 |
| ⑤ 사업 단계 원장 | **사업** 상세 | 단계 타임라인 한 줄(예정은 점선, 실제는 실선, 공정률) + KPI 3개(계획·공고 확인·공정률) + 근거 접힘 | 판본 이력 표, 정책 판단 작업 영역, 지역 여건 패널 |
| ⑥ 지역 여건 | **우리 동네** 시도 상세 | 숫자 4개(인구·가구·주택 재고·미분양) + 차트 1개(재고와 가구 추이) | 차트 10여 개, 산업별 종사자, 고용 반기 |
| ⑦ 원천 상태·확보 범위·연결 검토 | **데이터 원본** | 원천 상태 열(정상/실패·마지막 정상·기준일), 연도×원천 확보 격자, 연결 현황(검토 중/확정 건수) | API 연결 안내, 사업별 수집·연계 탭 |
| (보고) 정책 진행 | **보고자료** | 월간 브리핑에 '정책별 진행' 표 한 절(정책 × 6단계 목표/확인) | 별도 보고 화면 |
| (지도) 정책 사업 위치 | **지도** | 렌즈 칩 + 사업 점을 단계색으로 표시, 카드에 숫자 두 개(계획·공고 확인) | 3D 막대, 좌우 패널, 가상 건물 모형 |

**종합상황판**에는 렌즈 칩만 더한다. 정책을 고르면 판정과 리본이 그 묶음으로 좁혀진다. 카드는 늘리지 않는다.

**HOME에만 남기는 것**: 연결 승인, 목표 입력, 수집 실행처럼 쓰기가 필요한 기능이다. 우리 쪽은 그 결과만 가져온다. 나중에 우리 쪽에서 직접 해야 하면 메뉴 밖의 `/admin`(인증 필요)으로 만든다.

## 3. 깔끔한 UI 규칙

HOME의 복잡함을 하나씩 거꾸로 뒤집은 규칙이다. PRODUCT.md 원칙 1·3과 문구 최소화 피드백과 같은 방향이다.

| HOME에서 본 문제 | 우리 규칙 |
|---|---|
| 조작이 2줄에 10개 넘게 있다 | 조작은 칩 한 줄로 한다(렌즈·지역·단계·기간). 모든 선택을 URL에 남긴다 |
| KPI 6~7개 중 여럿이 '미확보'다 | KPI는 최대 3개만 둔다. 선택 범위 전체가 미확보인 KPI는 숨긴다 |
| 범례 상태가 7종이다(실색·사선·회색 점·빨간 격자·빨간 면 등) | 상태는 4가지로 줄인다: **확인**(실색) · **예정**(옅은 색) · **미확보**(빗금) · **지연**(빨간 테두리). 6단계 색은 그대로 쓴다 |
| 면책 문단이 화면마다 반복된다 | 머리 줄에 배지 하나와 툴팁만 둔다(예: '검토 중 연결', '공고 확인 ≠ 준공', '서울·인천·경기') |
| 같은 패널이 3~4곳에 나온다 | 정보는 한 곳에만 둔다. 지역 여건은 우리 동네, 근거는 사업 상세, 원천 상태는 데이터 원본에 두고, 다른 화면은 링크만 건다 |
| 한 화면에 차트가 여러 개 세로로 이어진다 | 화면마다 주인공 차트는 하나만 둔다 |
| 렌즈 범위(수도권)를 전국 화면과 헷갈릴 수 있다 | 렌즈를 고르면 범위 배지가 자동으로 붙는다. 기본값은 렌즈 없음(전체)이다 |

## 4. Supabase 이관: 데이터 자리

DDL(`supabase/migrations/20261011100500_ledger_schema.sql`)과 대조했다.

**이미 자리가 있는 것**

| HOME 자료 | 원장 표 |
|---|---|
| 정책 (`kind=policy`) | `ledger.policies` |
| 프로그램과 프로그램→정책 연결 | `ledger.programs` + `links(POLICY_PROGRAM)` |
| 사업과 사업→프로그램 연결 | `ledger.projects` + `identifiers`(HOME id 보관) + `links(PROGRAM_PROJECT)` |
| 계획 총량, 공고 확인 호수, 연도별 예정 호수 | `ledger.units` — `PROJECT_PLAN` / `NOTICE` / `AGENCY_PLAN`·`PUBLIC_PLAN` + `reference_period` |
| 단계 일정, 공정률 이력 | `ledger.events` — `PLANNED`(plan_basis) / `ACTUAL`, `PROGRESS` + `progress_pct` |
| LH 모집공고 | `ledger.notices` + `notice_links` |
| 연도별 공식 실적 | `ledger.stat_facts`. 기간만 2018-01까지 늘리면 된다(지금은 2021-09부터) |

**상태값 대응**: 우리 `review_status`는 `CONFIRMED`와 `REVIEW_REQUIRED` 둘뿐이다. HOME의 `REVIEW`는 `REVIEW_REQUIRED`로, `CONFIRMED`는 `CONFIRMED`로 옮긴다. `RELEASED`는 연결이 해제된 것이므로 적재하지 않는다.

**추가할 마이그레이션**(모두 덧붙이기만 하므로 기존 화면에 영향이 없다)
1. `ledger.policy_targets`: 정책, 단계, 범위 지역, 기간, 호수, 근거. 지금 policies 표에는 목표 열이 없다.
2. `ledger.area_facts`: 지역 코드, 지표, 기간, 값, 단위. 인구·가구·재고·미분양을 담는다.
3. `screen_snapshots.key`의 check 제약 확장과 `publish_screens` 키 검증 수정.
4. (선택) `stat_facts.metric`에 멸실 추가.

**받는 방법**: HOME 공개 읽기 API를 주 1회 받는다. 외부 접근이 되고 응답은 0.1~0.3초다(2026-10-13 확인). 받은 원문은 `raw/home10/`에 보관하고 원장에 적재한 뒤, 화면 값은 `api.screens`로 공개한다. 받기가 실패하면 지난 성공본을 유지한다.

## 5. 순서와 확인 기준

| 단계 | 내용 | 확인 |
|---|---|---|
| D0 | **시안 먼저**: 사업(렌즈·요약 띠·표·상세), 공급 실적 연도별 보기의 HTML 시안 | 사용자 확인 |
| D1 | 공급 실적 '연도별' 보기. 우리 자료만 쓰고 HOME에 의존하지 않는다 | HOME 2025년 값 9개를 고정값 시험으로 대조(이미 일치 확인) |
| D2 | 추가 마이그레이션 + HOME 받기 → 원장 적재 + 우리 LH 후보와 식별 대조 보고서 | 건수가 HOME과 같음, 같은 블록 중복 0 |
| D3 | 사업 화면 새로 만들기 | 9·7 단계 목표/확인 값을 HOME과 고정값 시험으로 대조, 글자 범위 측정(1440·1280·900) |
| D4 | 렌즈 공유: 종합상황판·지도, 보고자료 정책 절 | 같은 렌즈일 때 화면끼리 숫자가 같음 |
| D5 | 우리 동네 여건. 수도권은 HOME 자료로 하고, 전국으로 넓히려면 KOSIS·SGIS 키가 필요하다 | 원천 값 대조 |
| D6 | 데이터 원본: 원천 상태·확보 격자·연결 현황 | 원천 수가 HOME과 같음 |

D1은 바로 시작할 수 있다. D3·D4는 D2가 끝나야 한다.

## 6. 정할 것

1. HOME 자료를 받아 다시 공개해도 되는지 저장소 소유자와 합의해야 한다.
2. 렌즈 칩을 넣을 화면 범위를 정해야 한다. 사업만 넣을지, 종합상황판·지도까지 넣을지 결정한다.
3. 우리 동네 여건을 수도권만 먼저 열지, 전국 키를 확보한 뒤에 열지 정해야 한다.

## 7. 남은 불확실성

- HOME 최신 커밋(21c60b1)의 지표 정의 모듈(`policy_delivery`, `stage_evidence`, `identity`)은 아직 읽지 않았다. D2를 시작하기 전에 확인해야 한다.
- HOME 사업 308건과 우리 LH 후보 273건이 얼마나 겹치는지는 D2 대조에서 처음 알 수 있다.
- 멸실 지표의 원천은 확인하지 못했다.

## 1. 코드 표준

**표준코드는 법정동(10자리)** 입니다. 모든 코드는 **문자열**로 다룹니다(앞 0 보존, 숫자형 변환 금지). 행정동은 연계 조회용 입력 편의일 뿐 저장·API 키가 아닙니다.

### 1.1 AreaRef 종류

| 종류 | 형식 | 예(형식 설명용) | 쓰임 |
|---|---|---|---|
| `sido` | 숫자 2 | `28` | 시도. 집계·안내 |
| `sgg` | 숫자 5 | `28245` | 시군구. 지역 번들 단위(`region.json` `codes`) |
| `bjd` | 숫자 10 | `1129013800` | 법정동(읍면동·리). **저장·API 키** |
| `pnu` | 숫자 19 | `1129013800103160002` | 필지 = 법정동 10 + 대지구분 1 + 본번 4 + 부번 4 |
| `project` | `PRJ-{시군구5}-{일련4}` | `PRJ-28245-0003` | 사업(상황판 내부 id, 9절) |
| `adm` | 숫자 10(행정기관코드) | — | **입력 전용**. 법정동 집합으로 바꿔 쓰고 저장하지 않음 |

### 1.2 판별 규칙

`?code=`처럼 종류를 모르는 입력은 아래 순서로 판별합니다. `?sgg=` `?bjd=` `?pnu=` `?project=`처럼 종류를 밝히면 판별을 건너뛰고 형식만 검사합니다.

| 입력 | 조건 | 판별 | 처리 |
|---|---|---|---|
| 숫자 2자리 | — | `sido` | 시도 표 검증 |
| 숫자 5자리 | — | `sgg` | 시군구 표 검증 |
| 숫자 8자리 | — | `bjd` | 끝에 `00`을 보충해 10자리로 정규화(V-World `emd_cd` 형식), 응답 `warnings`에 `padded-8-digit`. 통계청 8자리 분류코드와는 모양이 같아 구분할 수 없으므로 **표 존재 검증을 통과해야 인정** |
| 숫자 10자리 | 법정동 표에 있음 | `bjd` | — |
| 숫자 10자리 | 법정동 표에 없고 행정동 연계표에 있음 | `adm` | 법정동 집합으로 변환(1.5). **연계표를 적재한 뒤(S5)에만** 판별. 그 전에는 법정동 표에 없는 10자리로 보고 1.4로 후퇴시키되 안내문에 "행정동 코드일 수 있음"을 덧붙임 |
| 숫자 10자리 | 두 표에 모두 있음 | `bjd` 우선 | 응답에 `ambiguous: true`, `alternatives: ["adm"]`. 같은 10자리가 두 표에 겹치는 빈도는 확인하지 못함 |
| 숫자 19자리 | — | `pnu` | 앞 10자리를 법정동으로 검증 |
| `PRJ-` 접두 | `^PRJ-\d{5}-\d{4}$` | `project` | 사업 id 발급 전에는 501(계약만. 현재 `resolve`는 `PRJ-`를 숫자가 아닌 입력으로 보고 400 `invalid-code`) |
| 그 밖 | 숫자가 아님·길이 불일치·모르는 시도 | 오류 | 400 `invalid-code`(`reason`: `empty` `not-digits` `unknown-sido` `bad-length` `bad-pnu`). 후퇴하지 않음 |

### 1.3 검증 순서 (`resolve`)

| 순서 | 검증 | 실패 시 |
|---|---|---|
| 1 | 정규화: 앞뒤 공백 제거, 숫자·`PRJ-` 형식, 길이 | 400 |
| 2 | 종류 판별(1.2), 8자리는 `00` 보충 | 400 |
| 3 | PNU 구조: 대지구분 1자리, 본번·부번 숫자(대지구분 허용 값은 1·2로 제한하는 것을 제안. 그 밖의 값이 쓰이는지는 확인하지 못함) | 400 |
| 4 | 표준코드 표 존재: 시도 → 시군구 → 읍면동·리 순(24시간 캐시) | 후퇴(1.4) |
| 5 | 필지·경계 조회(V-World, 24시간 캐시) | 후퇴(1.4) |
| 6 | 커버리지 판정(4절): 번들 `codes`와 시군구 비교 | — |
| 7 | 응답 조립: `requested`와 `resolved`를 모두 담고 `meta`를 붙임 | — |

표 조회가 불가능하면(키 소진·원천 장애) 번들 `codes`와 일치하는 코드는 `validation: "bundle-only"`로 통과시키고, 그 밖의 코드는 503 `not-configured` 또는 502 `upstream`입니다(**제안, 미구현**. 구현은 번들 코드도 표를 거쳐 429·503·502로 답합니다. 통과시키려면 `regions/index.json`에 시군구 코드를 두어 브라우저가 API 없이 지역을 고를 수 있어야 합니다).

### 1.4 후퇴 규칙

후퇴는 조용히 하지 않습니다. 응답에 `requested`·`resolved`·`warnings[]`를 모두 담고, 화면은 "요청한 코드는 없어 시군구로 열었습니다"를 배너로 알립니다.

| 상황 | 후퇴 | `warnings` |
|---|---|---|
| PNU 형식은 맞으나 V-World에 필지가 없음 | 법정동(앞 10자리) | `parcel-not-found` |
| 법정동이 표에 없음 | 시군구(앞 5자리)가 표에 있으면 시군구 | `bjd-not-found` |
| 시군구가 표에 없음 | 시도(앞 2자리)가 표에 있으면 시도 | `sgg-not-found` |
| 시도도 표에 없음 | 후퇴 없음. 404 `unknown-code` | 안내문에 "개편 전 코드일 수 있음"(추정: 표에는 과거 코드가 없음) |
| 리 단위 코드(끝 2자리가 `00`이 아님) | 읍면동 경계로 표시 | `ri-uses-umd-boundary`(추정: 리 경계 레이어를 확인하지 못함) |
| 경계 조회 실패 | 경계 없이 진행(번들이 있으면 지도는 열림) | `boundary-not-found`·`geometry-unavailable` |
| 번들 없음 | 경계만(등급 C) | 오류가 아님 |

**구현 상태(2026-10-05)**: 위 표 중 아래만 구현했습니다. 나머지(법정동·시군구·시도 단계별 후퇴)는 **제안이며 미구현**입니다.

| 상황 | 구현된 동작 | `warnings` | 지도 위 안내 |
|---|---|---|---|
| 필지가 V-World에 없음 | 법정동 경계로 열림 | `parcel-not-found` | "요청한 필지를 찾지 못해 법정동 경계로 열었습니다" |
| 리 단위 코드 | 읍면동 경계로 표시 | `ri-uses-umd-boundary` | "리(里) 경계는 없어 읍면동 경계로 표시합니다" |
| 경계 조회 실패 | 경계 없이 응답(지역 번들이 있으면 기본 위치로 열림) | `boundary-not-found` `geometry-unavailable` `geometry-not-configured` | "경계를 …불러오지 못해 지역 기본 위치로 열었습니다" |
| 시군구가 표에 없음 | **후퇴하지 않고 404** `unknown-code` | — | 오류 화면(지역 목록 링크) |
| 법정동이 표에 없음(시군구는 있음) | **후퇴하지 않고 404** `unknown-code`, 같은 시군구의 읍면동 8곳을 `suggestions`로 줌 | — | 오류 화면 |
| 번들 없음(등급 C) | 응답은 200, `coverage.tier: "none"` | — | "공급 사업 정보가 아직 없는 지역입니다" 안내 화면(경계만 그리는 지도는 준비 중) |

### 1.5 법정동↔행정동 변환 규칙

| 규칙 | 내용 |
|---|---|
| 저장 | 법정동만 저장합니다. 행정동은 입력 시점에 변환하고 버립니다 |
| 변환 | 행정동 입력 → 연계표로 **법정동 집합**(`bjd[]`)을 만듭니다. 한 행정동이 여러 법정동을 포함하고 한 법정동이 여러 행정동에 걸치는 **다대다**입니다 |
| 지도 | 행정동 경계 폴리곤은 V-World 법정읍면동 레이어로 얻을 수 없습니다(행정동 경계 레이어는 확인하지 못함). 집합 안 법정동 경계의 합집합으로 표시합니다 |
| 안내 | "이 동네는 법정동 N곳에 걸쳐 있어 일부 사업이 인접 동에 있을 수 있습니다"를 보입니다 |
| 역변환 | 법정동 → 행정동은 표시용 힌트에만 씁니다. 키로 쓰지 않습니다 |
| 가중치 | 1차는 가중치 없음. 비율 표시가 필요하면 2차로 인구 가중치(행정안전부 주민등록 인구 API)를 씁니다 |
| 이용허락 | 연계정보 CSV는 공공저작물 제3유형(출처표시·변경금지)이므로 원본을 재배포하지 않고 로컬 캐시에서 조회에만 씁니다. 조회용 색인으로 가공하는 것이 변경금지에 걸리는지는 확인하지 못함 |
| 적재 | 연계표 적재는 이번에 하지 않습니다(S5). 그 전에는 행정동 입력을 지원하지 않고 지도는 법정동 코드만 받습니다. 근거는 조사기록 2절 |

## 2. 진입 계약

### 2.1 쿼리 매개변수

현재 지도 앱은 `/`(`index.html`)이고, Next.js 이식 후에는 `/map`입니다. 쿼리 계약은 같습니다.

| 매개변수 | 값 | 동작 | 상태 |
|---|---|---|---|
| `code` | AreaRef 아무 종류 | 1.2로 판별해 연다 | 구현됨 |
| `sgg` | 5자리 | 시군구로 연다 | 구현됨 |
| `bjd` | 10자리(8자리 허용). 쉼표로 여러 개(최대 10, 제안) | 법정동 경계 강조·이동. 여러 개면 합집합 | 단일 값 구현됨, 여러 개는 계약만(현재 쉼표 목록은 400) |
| `pnu` | 19자리 | 필지 강조·이동. 건물 레이어는 `pnu`로 거를 수 없어 필지 폴리곤과 **공간 교차**로 잇는다 | 구현됨 |
| `project` | `PRJ-…` | 사업으로 연다 | 계약만 |
| `region` | slug | 기존 방식. 그대로 동작 | 유지 |
| `block` `mode` `panel` 등 | README.md 표 | 기존 방식. 그대로 동작 | 유지 |

- **우선순위**: `project` > `pnu` > `bjd` > `sgg` > `code`(판별 결과 기준) > `region`. 여러 개가 오면 앞선 하나만 쓰고 나머지는 무시합니다.
- **`region`과 코드가 함께 오면** 코드가 가리키는 번들 지역이 우선합니다. 코드가 번들 없는 지역이면 `region`은 무시하고 경계만 엽니다.
- **번들 있는 지역(등급 A)**: 번들을 열고 경계·필지를 강조하고 이동합니다. 구현: 법정동은 줌 15.4, 필지는 줌 17.6으로 이동하고(`?at=`가 있으면 그 위치가 우선), 경계는 주황 선으로 그립니다(법정동은 점선·옅은 면, 필지는 실선·짙은 면). **번들 없는 지역(등급 C)**: "공급 사업 정보 없음 · 경계만(준비 중)"을 안내합니다. 구현은 안내 화면과 지역 목록 링크까지이고 경계만 그리는 지도는 준비 중입니다.
- 해석 API를 못 쓰는 환경(정적 서버 404·405, 연결 실패, 한도 소진 429)에서는 지도를 열지 않고 사유와 지역 목록을 보입니다. `?region=`만 있는 주소는 해석 API를 부르지 않습니다.
- `?code=`로 열어도 기존 `?region=` 링크는 깨지지 않습니다.

### 2.2 팝업 열기 (상황판 쪽 코드 예시)

팝업 이름을 고정(`housing-map`)해 두면 두 번째 클릭부터 같은 창을 재사용합니다. `noopener`를 쓰지 않는 것은 같은 출처 통신(2.4)을 열어 두기 위해서입니다. 대신 팝업 안의 외부 링크는 `rel="noopener noreferrer"`로 겁니다.

```ts
// 상황판(클라이언트 컴포넌트)
type MapRef = { code?: string; sgg?: string; bjd?: string; pnu?: string; project?: string };

export function openMapPopup(ref: MapRef): boolean {
  const qs = new URLSearchParams(
    Object.entries(ref).filter(([, v]) => v) as [string, string][],
  ).toString();
  const win = window.open(`/map?${qs}`, 'housing-map', 'popup=yes,width=1280,height=860');
  if (!win) return false;      // 팝업 차단: 호출한 쪽이 새 탭 링크(<a target="_blank" rel="noopener">)를 보인다
  win.focus();
  return true;
}
```

### 2.3 프레임 임베드 차단 (iframe 배제)

지도 페이지는 어떤 출처의 `<iframe>`에도 들어가지 않습니다. 헤더 두 개를 **함께** 보냅니다(구형 브라우저는 앞의 것, 현행 브라우저는 뒤의 것).

```json
{ "source": "/(.*)", "headers": [
  { "key": "X-Frame-Options", "value": "DENY" },
  { "key": "Content-Security-Policy", "value": "frame-ancestors 'none'" }
] }
```

- 현재: `vercel.json`의 `headers`(`/(.*)`)에 위 두 항목이 있고 로컬 `scripts/dev.js`도 같은 헤더를 보냅니다(구현됨, `tests/js/vercelconf.test.cjs`. 저장소의 HTML·JS에 `<iframe>`이 없음도 시험). 실제 배포 응답은 배포한 뒤 확인합니다.
- Next.js 이식 후: `next.config.ts`의 `headers()`에서 `/map`과 상황판 전체에 같은 값을 보냅니다. 나중에 전체 CSP를 도입하면 `frame-ancestors 'none'`을 그 안에 포함시킵니다.
- 팝업(`window.open`)은 최상위 창이라 이 헤더에 막히지 않습니다. 시험: 다른 출처 페이지의 `<iframe src="…/map">`이 빈 화면·콘솔 오류로 거부되는지 확인합니다.

### 2.4 팝업↔상황판 통신 (선택)

필요할 때만 씁니다. **같은 출처 `postMessage` 또는 `BroadcastChannel`만** 허용하고, 받는 쪽은 `event.origin === location.origin`을 검사합니다.

| 메시지(`type`) | 방향 | 내용 |
|---|---|---|
| `map:ready` | 지도 → 상황판 | `{ resolved: { kind, code }, at }` |
| `map:select` | 지도 → 상황판 | `{ project?: string, pnu?: string, at }` (사용자가 지도에서 단지·필지를 고름) |
| `board:focus` | 상황판 → 지도 | `{ ref: MapRef }` (열려 있는 팝업에서 다른 사업으로 이동) |

## 3. API v1 계약

### 3.1 공통 규칙

| 항목 | 규칙 |
|---|---|
| 경로·메서드 | `/api/v1/…`, `GET`(`HEAD` 허용). 그 밖은 405 |
| 쿼리 | **허용 목록에 있는 이름만**. 모르는 이름이 있으면 400(값을 바꿔 가며 CDN 캐시를 비켜 가는 호출 차단) |
| 형식 | JSON(`application/json; charset=utf-8`). 위치 자료는 GeoJSON FeatureCollection |
| 좌표 | WGS84(EPSG:4326), `[경도, 위도]` |
| 시각 | ISO 8601, 한국 시간 오프셋 포함(`2026-10-05T16:51:00+09:00`). 날짜는 `YYYY-MM-DD` |
| 낱말 | 정류소·노선·차량은 GTFS 낱말(3.5). `route_type`은 항상 `3`(버스) |
| 메타 | 모든 성공 응답에 `meta` = `{ provider, cityCode, fetchedAt, ttl, attribution }`. 원천이 준 제공 시각이 있으면 `sourceAsOf` 추가 |
| 오류 | RFC 7807 `application/problem+json`(3.6) |
| 비밀 | 응답·오류·로그에 인증키와 키가 든 원천 URL을 담지 않는다 |

### 3.2 엔드포인트

| 경로 | 쿼리 | 응답 | 원천 | 상태 |
|---|---|---|---|---|
| `GET /api/v1/resolve` | `code` 또는 `sgg`/`bjd`/`pnu` 중 하나, 선택 `geometry`(0 또는 1) | 3.3 | 표준코드 표, V-World | 구현됨(`project`는 계약만) |
| `GET /api/v1/codes/search` | `q`(필수, 2자 이상), `sido`, `sgg`, `limit`(기본 20, 최대 100) | `{ items: [{ code, kind, name }], meta }` | 표준코드 표(`locatadd_nm` 부분 일치) | 계약만 |
| `GET /api/v1/areas/{bjd}/bus/stops` | `buffer`(m, 기본 0, 최대 500) | FeatureCollection(Point, GTFS `stops`) | 공급자 `stopsNear` + 색인 | 계약만 |
| `GET /api/v1/areas/{bjd}/bus/routes` | — | `{ items: [Route], meta }` | 공급자 `routesAtStop` + 색인 | 계약만 |
| `GET /api/v1/bus/routes/{routeId}/positions` | — | FeatureCollection(Point, VehiclePosition). **요청 시에만** | 공급자 `positions` | 기존 `/api/bus`로 구현됨(요청 시에만·키 풀·로컬 캐시), v1 경로는 계약만 |

- `{routeId}`는 `{provider}:{cityCode}:{원천 노선 id}` 형식입니다(예 `tago:23:ICB365000050`, `seoul:11:{busRouteId}`).
- **색인에 없는 노선은 부르지 않습니다**(404 `route-not-indexed`). 키를 쓰는 열린 중계가 되는 것을 막기 위해서입니다. 현재 `api/bus.js`가 번들의 `busRoutes` 중 `live` 노선만 부르는 것과 같은 원칙입니다(구현됨).
- `stops`·`routes`는 24시간 색인만 읽습니다. 색인이 없는 지역은 이번에는 404 `index-not-built`이고, S3에서 온디맨드 생성(호출 상한은 그때 정함)을 붙입니다.

### 3.3 `resolve` 응답 (구현됨)

`GET /api/v1/resolve?bjd=2824510900`의 응답입니다(좌표 배열은 줄임, 실제 호출 결과의 모양).

```json
{
  "type": "bjd", "canonical": "2824510900", "input": "2824510900", "sgg": "28245", "bjd": "2824510900",
  "name": "인천광역시 계양구 박촌동", "level": "umd",
  "bbox": [126.7, 37.5, 126.8, 37.6], "center": [126.75159, 37.55078],
  "geometry": { "type": "Polygon", "coordinates": [[[126.7, 37.5], [126.8, 37.5], [126.8, 37.6], [126.7, 37.5]]] },
  "coverage": { "tier": "A", "slug": "incheon-gyeyang", "name": "인천 계양구", "updatedAt": "2026-10-03", "visibility": "public" },
  "source": { "code": "행정안전부 행정표준코드(법정동코드)", "geometry": "V-World 법정읍면동 경계(LT_C_ADEMD_INFO)" },
  "asOf": "2026-10-05"
}
```

| 필드 | 뜻 |
|---|---|
| `type` | 입력 종류 `sgg` `bjd` `pnu` |
| `canonical` · `input` | 정규화한 코드(8자리는 `00` 보충) · 받은 그대로 |
| `sgg` `bjd` `pnu` | 앞 5자리 · 법정동 10자리 · 19자리(있을 때) |
| `parcel` | PNU일 때: `jibun`(예 `177`) `landType`(`일반`·`산`) `hub`(건축HUB 인자 `sigunguCd` `bjdongCd` `platGbCd` `bun` `ji`) `geometry`(없으면 `null`) `addr` |
| `name` · `level` | 표준코드 표의 전체 주소명 · `sgg` `umd` `ri` |
| `bbox` · `center` | 경계가 있을 때만. WGS84 `[경도, 위도]` |
| `geometry` | 경계(링은 최대 600점으로 줄임). 시군구는 기본 생략이고 `geometry=1`이면 포함, 법정동·필지는 기본 포함 |
| `coverage` | `tier: "A"`(번들 있음, `slug`·`name`·`updatedAt`·`visibility`) 또는 `tier: "none"`(번들 없음). 운영 환경에서는 `visibility: "preview"` 지역을 번들 없음으로 본다(배포에서 빠지므로) |
| `warnings` | 1.4 표의 이름들 + `padded-8-digit` |
| `source` · `asOf` | 코드 원천·경계 원천 · 응답 날짜 |

**정식 v1 모양과의 차이(제안, 미구현)**: 위 모양은 PoC가 쓰는 최소형입니다. 정식에서는 ① 경계·필지를 GeoJSON FeatureCollection으로, ② `requested`·`resolved`를 함께, ③ 3.1의 `meta`(`provider` `fetchedAt` `ttl` `attribution`)를, ④ 등급을 A·B·C로 바꿉니다. 소비자가 지도 앱 하나뿐인 지금은 바꾸지 않고 상황판 본체가 붙을 때 맞춥니다.

### 3.5 GTFS 낱말 대응

| GTFS 필드 | 대상 | TAGO 원천 | 서울 원천 |
|---|---|---|---|
| `stop_id` | 정류소 | 정류소 id(번들 `infra.json`의 `stops[].id`) | 서울 정류소 고유 id(필드명은 활용신청 후 확인) |
| `stop_code` | 정류소 | 정류소 번호(번들 `stops[].no`) | 정류소 번호(확인 필요) |
| `stop_name` | 정류소 | 정류소 이름 | 정류소 이름 |
| 좌표 | 정류소 | 위·경도 | 확인 필요 |
| `route_id` | 노선 | `{provider}:{cityCode}:{노선 id}` | `seoul:11:{busRouteId 9자리}` |
| `route_short_name` | 노선 | 노선 번호(번들 `busRoutes[].no`, 예 `76`) | 노선 번호 |
| `route_long_name` | 노선 | `기점 - 종점` | 확인 필요 |
| `route_type` | 노선 | `3` | `3` |
| `route_desc` | 노선 | 노선 유형(간선버스 등) | 확인 필요 |
| `vehicle_id` | 차량 | `vehicleno` | `vehId` |
| `vehicle_label` | 차량 | `vehicleno` | `plainNo` |
| `current_stop_sequence` | 차량 | `nodeord` | `sectOrd` |
| `current_stop_name` (확장) | 차량 | `nodenm` | 확인 필요 |
| `timestamp` | 차량 | 없음(`null`) | `dataTm`(제공시간) |
| `occupancy_status` | 차량 | 없음 | `congetion`(원천 철자. 값의 뜻은 확인하지 못함) |
| 좌표 | 차량 | `gpslong`·`gpslati` | `tmX`·`tmY` 또는 `posX`·`posY`(**좌표계 확인하지 못함**, 어댑터에서 WGS84로 변환·검증) |

GTFS-RT의 `timestamp`는 POSIX 시각이지만 이 계약은 일관성을 위해 ISO 8601로 둡니다(차이 명시).

### 3.6 오류 (RFC 7807)

`Content-Type: application/problem+json`, 본문은 `{ type, title, status, code, detail }`이고 사유에 따라 필드가 더 붙습니다. `type`은 상대 URI(`/problems/{slug}`)이며 `code`가 `{slug}`와 같습니다. 오류 문구에는 인증키·원천 URL·원천의 오류 문구를 싣지 않습니다.

| slug | status | 조건 | 상태 |
|---|---|---|---|
| `invalid-query` | 400 | 허용하지 않는 쿼리 이름, 코드가 0개이거나 2개 이상 | 구현됨 |
| `invalid-code` | 400 | 형식·자릿수·시도·종류 불일치. `reason`: `empty` `not-digits` `unknown-sido` `bad-pnu` `bad-length` `type-mismatch` | 구현됨 |
| `unsupported-level` | 422 | 시도 단위(지도 대상 아님) | 구현됨 |
| `unknown-code` | 404 | 표준코드 표에 없는 시군구·법정동(`sgg`, 법정동이면 `suggestions`) | 구현됨 |
| `method` | 405 | `GET`·`HEAD` 이외 | 구현됨 |
| `keys-exhausted` | 429 | 용도의 키가 모두 한도에 닿음. **`Retry-After`**(다음 한국시간 자정까지 초)와 `retryAfterSec` | 구현됨 |
| `not-configured` | 503 | 해당 용도의 키 없음 | 구현됨 |
| `upstream` | 502 | 원천 오류·시간 초과. 상세 원인은 밖으로 내지 않음 | 구현됨 |
| `route-not-indexed` | 404 | 색인에 없는 노선 | 계약만 |
| `index-not-built` | 404 | 색인이 없는 지역 | 계약만 |
| `not-implemented` | 501 | 사업 id 미발급(`project` 입력) | 계약만 |

`/api/bus`는 v1로 옮기기 전까지 `{ "error": "<이름>" }` 모양을 씁니다: `query`(400) · `no-live-routes`(404) · `method`(405) · `keys-exhausted`(429, `Retry-After`) · `upstream`(502) · `not-configured`(503).

### 3.7 캐시 헤더

서버에는 로컬 캐시(7절)가 따로 있고, 아래는 CDN·브라우저에 주는 값입니다.

| 경로 | 서버 캐시 TTL | `Cache-Control` | 상태 |
|---|---|---|---|
| `resolve` 성공 | 24시간(표·경계·필지) | `public, s-maxage=300, stale-while-revalidate=300` | 구현됨 |
| `resolve` 오류 | 없음 | 400·404·422는 `public, s-maxage=60`(형식 오류는 3600), 429·5xx는 `no-store` | 구현됨 |
| `/api/bus` 성공 | `ttl`초(60초 이상) | `public, s-maxage={ttl − 서버 캐시에서 묵은 초}, stale-while-revalidate={ttl}` | 구현됨 |
| `/api/bus` 오류 | 실패는 15초만 | 400·404는 `s-maxage=3600`, 502는 `s-maxage=15`, 429·503은 `no-store` | 구현됨 |
| `codes/search` | 24시간 | `public, max-age=300, s-maxage=86400` | 계약만 |
| `areas/{bjd}/bus/stops`·`routes` | 24시간 | `public, max-age=300, s-maxage=86400` | 계약만 |
| `bus/routes/{routeId}/positions`(v1) | 60초(서울은 5.4의 계산값) | `public, max-age=0, s-maxage={ttl}`. 응답 `meta.ttl`과 같은 값 | 계약만 |

## 4. 데이터 공급 등급과 coverage

| 등급 | 뜻 | 보이는 것 | 상태 |
|---|---|---|---|
| **A** | 지역 번들이 있음(`regions/<slug>/`) | 단지·건물 3D·점검·버스 + 경계·필지 | 3개 지역 |
| **B** | 번들은 없으나 공개 API로 **요청 시** 가져올 수 있음 | 경계·필지 + 건축HUB 인허가(법정동 단위, 번지 단위 집계) + 버스 정류소·노선 | 미구현(S2) |
| **C** | 번들·온디맨드 모두 없음 | 경계만. "공급 사업 정보 없음 · 경계만(준비 중)" | 안내 화면까지 구현됨(경계 지도는 준비 중) |

- **판정**: 입력의 시군구 5자리가 번들 `region.json`의 `codes`(`type: "sigungu"`)와 같으면 A입니다. 번들 `codes`에 `bjdong` 항목이 있으면 `coverage.focus`에 담아 "번들의 사업은 이 법정동들 범위"로 안내합니다. 항목이 없으면 시군구 전체입니다. 번들 `bjdong` 코드는 **8자리**(`emd_cd` 형식)이므로 비교 때 `00`을 보충합니다.
- 코드→번들 색인은 `regions/index.json`과 각 `region.json`의 `codes`로 만듭니다. 새 번들을 추가하면 coverage가 자동으로 따라옵니다.
- 번들의 `codes`가 표준코드 표에 실제로 있는지는 직접 대조하지 않았습니다(확인하지 못함). resolve의 coverage 시험이 맡습니다.

| 번들 | 시군구 | `codes` 중 법정동 | 등급 |
|---|---|---|---|
| `incheon-gyeyang` | `28245` | 없음(시군구 전체) | A |
| `gwangju-gwangsan` | `12330` | `12330106` 운수동 · `12330107` 선암동 · `12330108` 소촌동 | A(법정동 3곳 범위) |
| `jeonnam-naju` | `12170` | `12170134` 빛가람동 | A(법정동 1곳 범위) |

### 5.1 공급자 어댑터 인터페이스

```ts

export interface BusProvider {
  id: 'tago' | 'seoul';
  /** 좌표 반경 안의 정류소 */
```

### 5.3 `bus-city-map` (시군구 → 공급자)

| `name-match` | TAGO 도시 목록과 이름만 일치 | 나주시(36040). 응답은 확인하지 못함 |
| `none` | 대응 없음 | 서울 25구, 전남광주 10 시군구, 강원 12 시군구 등 |

- 표준 시군구 269개 중 TAGO 도시와 이름이 일치하는 것이 210개(시도 이름 41 + 시군 이름 169), 대응이 없는 것이 59개입니다(서울 25 · 전남광주 10 · 강원 12 · 그 밖 12, 내역은 확인하지 못함). 자동 생성한 표는 모두 `name-match`이며 `response`로 올리려면 시군구마다 한 번 호출해 봐야 합니다.
- 서울 25구는 `{ "provider": "seoul", "cityCode": "11" }`로 둡니다. 서울 어댑터가 없는 동안은 `not-configured`로 응답합니다.

### 5.4 요청 시 조회와 호출 예산

**버스 위치는 요청 시에만 조회합니다.** 버튼 1회 = 스냅샷 1회이고, 자동 갱신·실시간 검색은 하지 않습니다. 새로고침은 `meta.ttl`(기본 60초) 동안 비활성인 **수동 버튼**입니다. 서버도 같은 시간 동안 응답을 재사용하므로 여러 사용자가 동시에 눌러도 원천 호출은 한 번입니다.

| 기호 | 뜻 |
|---|---|
| `n` | 한 요청이 부르는 노선 수(상한 8, 제안) |
| `ttl` | 서버 캐시 시간(초) |
| `L` | 서비스의 일일 한도(6.4) |
| `K` | 그 용도(`BUS`)에서 해당 서비스를 쓸 수 있는 키 수 |

```
일일 호출 상한(하루 종일 눌렀을 때)   U = n × ⌊86,400 ÷ ttl⌋
운영 조건                            U ≤ 0.8 × L × K            (20%는 여유)
필요한 ttl                           ttl = max(60, ⌈ n × 86,400 ÷ (0.8 × L × K) ⌉)
```

구현: `api/bus.js`의 `ttlFor(노선 수, BUS 키 수) = max(60, ⌈노선 수 × 86,400 ÷ (8000 × K)⌉)`이며 `8000`은 `0.8 × 10,000`(`DAILY_BUDGET`), `K`는 키 풀의 `count('BUS')`입니다. 아래 표의 값이 시험으로 재현됩니다(`tests/js/busapi.test.cjs`). 응답 `ttl`은 같은 값이고 화면 쿨다운이 따라갑니다. 노선 수 상한 8은 제안이며 지금은 번들의 `live` 노선 수(계양 4개)가 정합니다.

| 경우 | n | L | K | U (ttl 60) | 조건 충족 | 필요한 ttl |
|---|---|---|---|---|---|---|
| TAGO 계양(실시간 4개 노선) | 4 | 10,000 | 1 | 5,760 | 예(≤ 8,000) | 60초 |
| TAGO 노선 8개 | 8 | 10,000 | 1 | 11,520 | 아니오 | 87초 |
| 서울 노선 1개 | 1 | 1,000 | 1 | 1,440 | 아니오(> 800) | 108초 |
| 서울 노선 4개 | 4 | 1,000 | 1 | 5,760 | 아니오 | 432초 |
| 서울 노선 4개, 키 3개 | 4 | 1,000 | 3 | 5,760 | 아니오(> 2,400) | 144초 |

### 5.5 서울 개발 1,000건/일 한도 대응

| 방법 | 내용 |
|---|---|
| ttl 연장 | 위 계산식의 `ttl`을 서울 한도로 계산해 `meta.ttl`에 담는다. 화면 쿨다운이 따라 늘어난다 |
| 노선 수 제한 | 서울은 한 요청에 노선 1~2개로 제한한다(제안) |
| 키 분산 | `BUS` 키를 늘려 `K`를 키운다(6절). 키마다 서울 서비스 활용신청이 따로 필요하다 |
| 운영계정 증설 | 활용사례를 등록하면 증설할 수 있다. 수치는 공시되지 않아 확인하지 못함 |
| 한도 오류 | 6.3의 소진 처리 후 다음 키로 넘기고, 모두 소진이면 429 |

## 6. 키 관리

공공데이터포털 인증키는 개발·시연용으로 **여러 개**를 받고, 한도를 감안해 **용도별로 나눠** 씁니다.

### 6.1 변수 이름

| 변수 | 뜻 |
|---|---|
| `DATA_GO_KR_KEY_<PURPOSE>_<N>` | 용도별 키. `N`은 1, 2, … |
| `DATA_GO_KR_KEY` | 기본(호환). 용도별 키가 없거나 **모두 한도에 닿았을 때만** 쓴다 |
| `DATA_GO_KR_SERVICES_<PURPOSE>_<N>` | 그 키로 활용신청한 서비스 목록(`'tago,hub'`). 없으면 모든 서비스 가능으로 본다 |
| `DATA_GO_KR_LIMITS` | 서비스별 일일 한도 덮어쓰기(`'tago=10000,seoul=1000'`) |
| `DATA_GO_KR_PROFILE` | `demo`로 두면 서버가 쓰는 용도(`BUS`·`RESOLVE`)는 `DATA_GO_KR_KEY_DEMO_<N>` 키를 먼저 쓴다. `DEMO` 키가 없으면 개발 키. `BUILD`는 영향받지 않는다 |
| `VWORLD_KEY` | V-World 키(기존). 서버의 경계·필지 조회에도 쓴다. 서버 호출 시 도메인 등록 조건은 확인하지 못함 |

| `PURPOSE` | 용도 | 호출 예 |
|---|---|---|
| `BUILD` | 번들·색인 배치 | 정류소·노선 색인, `infra.json` 빌드, 건축HUB 수집 |
| `RESOLVE` | 코드 해석 | 표준코드 표 갱신 |
| `BUS` | 버스 요청 시 조회 | 차량 위치 |
| `DEMO` | 시연 | 발표·시연 전용. `DATA_GO_KR_PROFILE=demo`일 때 `BUS`·`RESOLVE` 대신 쓴다. 개발 중 소진돼도 시연이 막히지 않게 분리 |

### 6.2 `.env.local` 예시 (값은 자리표시자)

```
# 공공데이터포털 인증키. 값은 저장소·로그·문서에 남기지 않는다(.env* 는 gitignore).
# 서버 전용: NEXT_PUBLIC_ 접두를 붙이지 않는다.
DATA_GO_KR_KEY=…
DATA_GO_KR_KEY_BUILD_1=…
DATA_GO_KR_KEY_RESOLVE_1=…
DATA_GO_KR_KEY_BUS_1=…
DATA_GO_KR_KEY_BUS_2=…
DATA_GO_KR_KEY_DEMO_1=…
DATA_GO_KR_SERVICES_BUS_1='tago'
DATA_GO_KR_SERVICES_BUS_2='tago,seoul'
DATA_GO_KR_LIMITS='tago=10000,seoul=1000,stan=10000,hub=10000'
# DATA_GO_KR_PROFILE=demo      # 시연일에만. ./run-app.sh 도 같은 환경변수를 받는다
```

견본은 저장소 루트의 `env.example`(값 없음)입니다. 용도 이름은 대문자·숫자만, 번호는 1부터입니다. 키는 포털의 **디코딩 값**을 그대로 적고(`+` `/` `=` 허용, 인코딩된 채여도 읽을 때 한 번 디코딩) 요청할 때 한 번만 인코딩합니다.

### 6.3 선택 알고리즘 (`lib/keys.js`, 구현됨)

| 단계 | 동작 |
|---|---|
| 1 | 후보 = 요청 용도의 키 중 그 서비스를 신청한 키(`DATA_GO_KR_SERVICES_*`, 없으면 모든 서비스 가능). `demo` 프로파일이면 `BUS`·`RESOLVE`는 `DEMO` 키를 후보로 한다. 후보가 비면 `DATA_GO_KR_KEY`. **다른 용도의 키를 빌려 쓰지 않는다**(시연 보호) |
| 2 | 후보 중 오늘(한국시간) 그 서비스를 **가장 적게 쓴** 키를 고른다(같으면 돌려 가며). 일일 한도에 닿았거나 소진 표시가 있는 키는 뺀다 |
| 3 | 호출하고 사용량을 1 올린다(실패도 센다) |
| 4 | **한도 오류**(`resultCode` 22 JSON, XML 본문의 `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR`·`returnReasonCode` 22, HTTP 429)면 그 키·서비스를 **다음 한국시간 자정까지 소진** 처리하고 같은 요청 안에서 다음 후보로 다시 시도한다 |
| 5 | 후보가 모두 소진이면 429 `keys-exhausted` + `Retry-After`. 용도에 키가 아예 없으면 503 `not-configured` |

빌드 도구(Python, `tools/regiontools/api.py`)는 `DATA_GO_KR_KEY_BUILD_<N>`을 번호 순으로 읽어 **한도 오류가 나면 다음 키로** 이어서 부르고(같은 쪽을 다시 요청), 키 하나만 있으면 `DATA_GO_KR_KEY`를 씁니다. 한 번 실행 안의 순환이며 JS처럼 날짜별 사용량 파일은 공유하지 않습니다. 모두 소진이면 `QuotaExceeded`로 멈춥니다.

### 6.4 서비스별 일일 한도 (기본값)

| 서비스 | 대상 | 기본 한도 | 비고 |
|---|---|---|---|
| `tago` | TAGO 위치·정류소·노선 | 10,000 | 세 서비스를 합쳐 센다(보수적. 포털은 서비스·오퍼레이션별로 셀 수 있음, 확인하지 못함) |
| `seoul` | 서울 위치·정류소·노선 | 1,000 | 개발계정 |
| `stan` | 행정표준코드 법정동코드 | 10,000 | |
| `hub` | 건축HUB 주택·건축인허가 | 10,000 | 포털 표기는 오퍼레이션별 |
| `myhome` | 마이홈 공고 | 10,000 | |

새 서비스(예: 주민등록 인구 현황)를 신청하면 표에 이름과 한도를 추가합니다.

### 6.5 사용량 카운터

로컬은 `.cache/key-usage.json`에, **한국시간 날짜가 바뀌면 전날 값을 버립니다**(자정 초기화). 라벨별·서비스별로 셉니다.

```json
{ "date": "2026-10-05",
  "counts": { "BUS_1": { "tago": 412 }, "BUS_2": { "seoul": 37 } },
  "exhausted": { "BUS_2": { "seoul": true } } }
```

사용 현황은 `pool.usage()`가 라벨만으로 돌려줍니다(`{ date, keys: { BUS_1: { tago: { used, limit, exhausted } } } }`). 개발 서버는 시작할 때 `키: BUS 2개 · RESOLVE 1개`처럼 **개수만** 찍습니다.

**서버리스(Vercel)** 에서는 파일을 공유할 수 없어 인스턴스 메모리 카운터를 씁니다(인스턴스가 바뀌면 0부터). 일일 합계를 정확히 알 수 없으므로 5.4의 80% 여유를 두고, 한도 오류를 받으면 그 인스턴스에서 키를 쉬게 합니다. `해시(서비스, 노선, ttl 시간창) mod 키 수`로 인스턴스와 상관없이 같은 키를 쓰게 하는 **결정적 분산은 제안이며 미구현**입니다.

### 6.6 노출 금지 규칙

| 규칙 | 내용 |
|---|---|
| 접두 | `NEXT_PUBLIC_` 금지(`DATA_GO_KR_*`는 서버 전용). V-World 배경지도 키는 현재도 브라우저에 보이는 도메인 제한 키이므로 `NEXT_PUBLIC_VWORLD_KEY`로 두는 것을 허용(제안) |
| 라벨 | 로그·응답·오류에는 `BUS_2`처럼 **라벨만** 씁니다 |
| URL·원인 문구 | 원천 호출 URL과 원천이 준 오류 문구는 응답에 싣지 않고 고정 문구만 씁니다(구현됨). Python 도구는 오류 문구의 키를 `redact()`로 `<KEY>`로 가립니다 |
| 캐시 | 캐시 파일·카운터에 키 값을 넣지 않습니다 |
| 점검 | 시험(구현됨): 응답·`pool.usage()`·캐시 파일·사용량 파일에 테스트 키 문자열(원문·인코딩형)이 없는지 검사합니다(`tests/js/busapi.test.cjs`). 개발 서버 로그에도 키 개수만 나옵니다 |

한도가 키 단위인지 계정 단위인지, 여러 키를 어떻게 확보하는지에 따라 합산 한도가 달라집니다. 계정을 여러 개 만들어 한도를 나누는 방식이 이용약관에 맞는지는 확인하지 못함(기획서 8절 질문).

## 7. 캐시

로컬 캐시에 저장하고 **짧게 보관**합니다. 원천 응답은 **재배포하지 않습니다**(이용허락 조건이 소스마다 달라 보수적으로). API는 필요한 필드(코드·이름·좌표)만 돌려주고 출처를 표시합니다.

| 대상 | TTL | 저장 위치 | 키 |
|---|---|---|---|
| 표준코드 표 | 24시간 | `.cache/<해시>.json` + 메모리(파일 이름은 키의 SHA-1, 파일 안에 원래 키를 둠) | 시군구(`sido_cd`+`sgg_cd`로 받음). `region_cd`는 필터가 아니라서 시도 전체가 아니라 시군구 단위로 받음 |
| 경계 · 필지 | 24시간 | 같은 방식 | `vw:<레이어>:<코드>`(시군구·읍면동 경계, 필지 PNU) |
| 정류소 · 노선 색인 | 24시간 | `.cache/<해시>.json` + 메모리 | 공급자·도시. **미구현**(S3) |
| 버스 위치 | `ttl`초(60초 이상, 서울은 5.4 계산값) | 파일+메모리 | `bus:<지역>`(그 지역 live 노선 전체를 한 덩어리로). 실패는 `bus-fail:<지역>` 15초 |
| 키 사용량 카운터 | 한국시간 자정 초기화 | `.cache/key-usage.json` | 라벨·서비스·날짜 |

| 규칙 | 내용 |
|---|---|
| 위치 | 로컬은 저장소의 `.cache/`(`.gitignore`에 있음). `CACHE_DIR`로 바꿀 수 있고 Vercel은 `os.tmpdir()/jt-cache` |
| 만료 | 읽을 때 만료됐으면 지우고 다시 조회합니다. 원천이 실패해도 만료 항목을 쓰지 않고 오류를 돌려줍니다(짧게 보관 원칙, 바꾸려면 합의). 같은 키를 동시에 요청하면 원천은 한 번만 부릅니다 |
| 총량 상한 | 50 MB. 쓸 때마다 합계를 재고 넘으면 **오래된 파일(수정 시각)부터** 지웁니다. 개발 서버는 시작할 때 만료된 파일도 정리합니다. TTL 상한은 호출한 쪽이 정해도 24시간으로 잘립니다 |
| 서버리스 | 파일은 `/tmp`와 인스턴스 메모리만 씁니다. 인스턴스가 바뀌면 사라지는 것을 전제로 합니다 |
| 원본 파일 | 연계정보 CSV 등 내려받은 원천 파일은 저장소에 커밋하지 않고 `.cache/`에만 둡니다 |
| 크기 감각 | 표준코드 표 전체는 20,560행입니다. 행당 약 150 B로 잡으면 3 MB 안팎입니다(추정) |

## 9. 사업·데이터 모델

### 9.1 사업 레코드

| 속성 | 형식 | 필수 | 설명 |
|---|---|---|---|
| `id` | `PRJ-{시군구5}-{일련4}` | 필수 | 발급형 내부 id. 발급 후 불변. 시군구는 **발급 시점** 값이며 현재 시군구는 `sgg`가 정본(행정구역이 바뀌어도 id는 그대로) |
| `sgg` | 숫자 5 | 필수 | 현재 시군구 |
| `bjdCodes` | 문자열[10] | 필수(빈 배열 가능) | 사업이 걸친 법정동 |
| `pnus` | 문자열[19] | 필수(빈 배열 가능) | 사업 필지. 비면 지도에서 "위치 미연결"로 보임 |
| `stageCode` | `"01"`~`"06"` | 필수 | 6단계 |
| `source` | `{ provider, dataset, url? }` | 필수 | 원천기관·데이터셋 |
| `asOf` | `YYYY-MM-DD` | 필수 | 원천 기준일 |
| `refs` | `[{ system, key, value, asOf? }]` | 필수(1개 이상) | 외부 참조키. 수작업 입력 사업은 `system: "manual"` |
| `name` | 문자열 | 권장 | 표시 이름 |
| `units` | 정수 | 선택 | 호수 |
| `schedule` | `{ baseline, revised, current }` | 선택 | 당초·변경·현재 예정(지연 판정용, 후속) |

```json
{ "id": "PRJ-28245-0003", "sgg": "28245", "bjdCodes": [], "pnus": [], "stageCode": "04",
  "source": { "provider": "국토교통부", "dataset": "건축HUB 주택인허가정보" }, "asOf": "2026-08-26",
  "refs": [ { "system": "hub-hs-basis", "key": "mgmHsrgstPk", "value": "…" } ] }
```

| `refs.system` | 의미 | 키 필드 |
|---|---|---|
| `hub-hs-basis` | 건축HUB 주택인허가 기본개요 | `mgmHsrgstPk` |
| `hub-ap-basis` | 건축HUB 건축인허가 기본개요 | `mgmPmsrgstPk` |
| `seoul-redev` | 서울 정비사업 현황 | 확인하지 못함 |
| `vworld-upisuq161` | V-World 도시계획 구역 경계 | 확인하지 못함 |
| `manual` | 수작업 입력(예: 보도자료 기준) | 출처 제목·주소 |

- `refs.value`는 **문자열**로 보관합니다. 관리번호는 자릿수가 6·7·13·22로 섞이고 앞에 0이 붙으므로 숫자형 변환을 금지합니다.
- 한 사업·필지에 건축HUB 기록이 여러 개일 수 있어(변경허가·분할) 사업 하나에 `refs`가 여럿입니다. 건축HUB는 허가 이벤트 단위이므로 번지 단위로 집계해 사업을 만듭니다(레코드 단위 판정은 약 46% 오탐, 이전 실측).
- **사업↔PNU 연결**: 이번에는 하지 않습니다. 후보는 주택인허가 대지위치(`getHpPlatPlcInfo`)에서 지번을 읽어 PNU를 조립하는 방법이며 미검증입니다.

### 9.2 현재 5종 상태 ↔ 6단계 (제안, 합의 필요)

현재 번들의 `status`는 단지(블록) 단위 5종이고, 계산 규칙은 `docs/data-interface/정의서.md` 4절입니다.

| 현재 상태 | 정의서의 판정 | 6단계 제안 | 합의할 점 |
|---|---|---|---|
| `계획` | 그 밖의 모든 단지(사업승인만 있는 경우 포함) | 02 사업화 또는 03 인허가 | 사업승인(인허가) 이벤트가 있으면 03, 없으면 02로 가를지 |
| `분양중` | 공고가 있고 가장 최근 공고일이 12개월 안 | 05 공급 | 건설과 겹칠 수 있음(선분양). 단계 하나로 고정할지, 동시 표시할지 |
| `건설 단계` | 실제 착공 또는 공정율 > 0 | 04 건설 | — |
| `준공 임박` | 공정율 90 이상 + 입주 3개월 안 | 04 건설(말기) | 04 안의 세부 상태로 둘지, 06으로 넘길지 |
| `입주 단계` | 실제 준공검사 또는 입주 | 06 입주 | — |
| (없음) | — | 01 정책 | 현재 번들에 대응 상태가 없음(정책·공급계획 발표 단계) |

상태는 단지 단위이고 단계는 사업 단위이므로, **한 사업의 단지들이 서로 다른 상태일 때 사업의 단계를 정하는 규칙**(가장 앞선 단계? 호수 가중 대표?)이 필요합니다(미결).

### 9.3 원천 카탈로그 스키마

상황판의 '데이터 원본' 화면과 사업 상세의 "근거"가 읽는 목록입니다. 화면 요구사항은 기획서 4.2입니다.

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | 문자열 | 카탈로그 항목 id(예 `hub-hs-basis`) |
| `provider` | 문자열 | 제공기관(예 `국토교통부(공공데이터포털)`) |
| `dataset` | 문자열 | 데이터셋·API 이름과 오퍼레이션(예 `건축HUB 주택인허가정보 서비스 getHpBasisOulnInfo`) |
| `query` | `{ sgg, bjd, pages }` | 조회 조건(예 `{ "sgg": "11290", "bjd": "13800", "pages": "all" }`) |
| `collectedAt` | ISO 8601 | **우리가 받은 시각**(예 `2026-10-02T16:51:00+09:00`) |
| `sourceAsOf` | `YYYY-MM-DD` | **원천의 기준일**(예 레코드 생성일 `crtnDay` 최신 `2026-08-26`) |
| `count` | 정수 | 받은 건수 |
| `usedCount` | 정수 | 상황판에 쓰인 건수 |
| `description` | 문자열 | 한 줄 설명(선택) |
| `license` | 문자열 | 이용허락(선택) |
| `columns` | 문자열[] | 표에 보일 열(선택) |

`collectedAt`(받은 날)과 `sourceAsOf`(원천이 말하는 기준일)를 **반드시 구분**해 둡니다. 둘을 섞으면 "최신"을 잘못 읽게 됩니다.
